# Oleafly 写作一周

这就是 Oleafly 中论文的日常实际情况，从空项目到可以发送给合著者的草稿。该应用程序不需要帐户，也不需要服务器：项目是磁盘上“.tex”、“.bib”和图形文件的文件夹，下面的所有内容都在该文件夹上运行。

## 第一天：从模板开始

在库中创建一个项目，可以是空白项目，也可以使用常见格式（例如 IEEE 和 ACM 论文或论文框架）的[模板](/templates/)。模板会立即为您提供一个编译文档，其中类选项和序言已经合理，这比第一天逐行组装序言要好。在编写任何内容之前，按一次“编译”以确认您获得了 PDF。

## 周中：写入-编译循环

一周的大部分时间都是在编辑器和 PDF 窗格之间循环。编辑器会自动完成项目中存在的命令、环境以及标签和引用键，并且斜杠命令会插入更大的结构，例如图形和表格，而无需您记住其样板。经常编译，因为两分钟前编写的文本中很容易出现新的错误，而一下午的更改后出现的错误则不然。 SyncTeX 将两个窗格连接在一起：单击 PDF 中的一个段落可跳转到其源代码行，或从源代码跳转到 PDF，这在修改长文档的特定页面时最为重要。

## 随时引用

在项目中保留一个“.bib”文件，并在编写时使用“\cite{...}”进行引用，让自动完成功能提供键。在写作时添加参考文献的成本很低。重建三周的“需要引用”占位符则不然。如果条目来自 Zotero 或出版商的导出，[BibTeX 验证器](/tools/bibtex-validator/) 会在丢失的字段作为看起来奇怪的引用出现之前捕获它们。完整的流程在[从 .bib 键到文本引用](/learn/add-itations/) 中描述。

## 没有仪式的历史

Oleafly 可以在每次成功编译后自动记录 Git 提交，因此一周会留下您可以检查或回滚的工作状态时间表。当草稿值得分享时，将文件夹推送到私有 GitHub 存储库； [将论文放在 GitHub 上](/learn/sync-with-github/) 显示了设置。

## 可选：助手

如果您为托管提供商添加 API 密钥，或将应用程序指向本地 Ollama，助手可以回答有关您的项目的问题，提出批准差异背后的编辑建议，并进行编译以检查其自己的工作。可选：上面的每一步都可以在没有它的情况下工作。详细信息请参阅[Oleafly 内的助手](/learn/oleafly-ai/)，应用程序背后更广泛的设计意图位于[入门](/docs/getting-started/) 和[哲学](/docs/philosophy/)。
