# 當 LaTeX 打敗 Word 時（以及當它沒有打敗 Word 時）

這兩種工具都不是普遍更好。文字處理器針對直接操作進行了最佳化：您看到的就是文件。 LaTeX 最佳化結構：您以純文字描述文檔，然後編譯器對其進行排版。哪種模式獲勝取決於您面前的文件，而不是部落忠誠度。

## LaTeX 的學習曲線在哪裡

方程式是最清楚的情況。 Word 的方程式編輯器適用於家庭作業問題。跨越一百個帶有交叉引用的編號方程式變得很痛苦。在 LaTeX 中，無論您重新組織多少，「\label」和「\ref」都會保持每個數字的正確性，[交叉引用](/learn/cross-references/) 課程詳細介紹了這一點。

長結構化文件的行為方式相同。包含單獨文件中的章節、自動目錄和一致的標題樣式的論文在 LaTeX 中很常見，但在文字處理程序中卻很脆弱。引文遵循相同的模式：包含數百個條目的 BibTeX 資料庫會針對任何期刊風格重新格式化，而手動維護的參考文獻清單會很快退化。有關機制，請參閱[新增參考](/learn/add-itations/)。

隨著時間的推移，兩個更安靜的優勢會復合。 LaTeX 原始碼是純文本，因此 Git 可以清晰地比較和版本化它，並且相同的源代碼在幾年後在任何機器上生成相同的 PDF，沒有佈局漂移。

## Word 或 Google Docs 是正確的選擇

當協作是文件時，直接操作的編輯會獲勝。如果您的共同作者不是技術人員，只從事追蹤更改，並且需要在今天下午發表評論，那麼共享文件就是實際的答案。他們還贏得了簡短的一次性信件，其中 LaTeX 設置成本高於排版回報，以及只接受“.docx”文件的出版商或人力資源部門。

## 實用的混合體

將真實來源保留在 LaTeX 中，並為需要的人匯出草稿。 PDF收集評論； Pandoc 產生的 DOCX 符合「.docx」要求。這些回合的決定會合併回“.tex”文件，該文件仍然是規範版本。關於[與基於 Word 的協作者合作](/learn/collaborator-uses-word/) 的課程將介紹這個循環。

## 簡短的回答

使用 LaTeX 處理您在幾個月內要引用、編號、交叉引用或修改的任何內容。當 LaTeX 的社會成本超過其排版優勢時，請使用文字處理器。這兩種判斷都是合理的，大多數研究人員在特定年份使用這兩種工具。
