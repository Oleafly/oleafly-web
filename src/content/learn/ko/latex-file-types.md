# 실제 프로젝트의 파일

컴파일 후 실제 LaTeX 프로젝트의 폴더를 열면 작성한 것보다 훨씬 더 많은 파일을 찾을 수 있습니다. 이는 대부분의 초보자를 놀라게 하며, 잘못된 것을 삭제하는 것에 대한 두려움으로 인해 폴더가 영원히 복잡해집니다. 이를 명확하게 하는 차이점은 일부 파일은 사용자가 편집하는 소스이고, 일부 파일은 템플릿이나 패키지에서 제공하는 스타일이며, 나머지는 컴파일러가 실행될 때마다 다시 생성하는 생성된 스크래치 공간입니다.

## 당신이 작성한 파일

`.tex` 파일에는 텍스트, 섹션, 그림, 수학 등 실제 문서가 들어 있습니다. `.bib` 파일은 참고문헌 데이터베이스로, 인용할 수 있는 논문이나 책당 하나의 항목입니다. 직접 유지 관리하거나 Zotero와 같은 참조 관리자에서 내보낼 수 있습니다. 이 파일은 다른 모든 것을 다시 빌드할 수 있기 때문에 백업하고 버전 관리에 넣을 가치가 있는 파일입니다.

## 템플릿이 제공하는 파일

`.cls` 파일은 `\documentclass{...}`에 이름을 지정하는 문서 클래스를 정의합니다. 저널과 컨퍼런스는 자체적으로 배송되므로 모든 제출물이 동일하게 보이고 편집할 일이 거의 없습니다. `.sty` 파일은 `\usepackage`로 로드된 재사용 가능한 매크로 및 설정 패키지입니다. 여러 문서에서 사용자 정의 명령을 공유하려는 경우에만 직접 작성하면 됩니다. `.bst` 파일은 BibTeX 인용 스타일을 설명하며 마찬가지로 일반적으로 장소에 드롭됩니다.

## 컴파일러가 만드는 파일

`.aux` 파일은 컴파일 패스 간의 상호 참조 및 인용 데이터를 저장합니다. 절대 편집하지 말고, 자유롭게 삭제해도 됩니다. 다음 컴파일에서 다시 작성하기 때문입니다. `.log` 파일은 컴파일러가 수행한 모든 내용을 기록하며 문제가 발생한 경우에만 열 가치가 있습니다. `.pdf`는 실제로 원하는 출력입니다.

| 확장 | 역할 | 직접 편집하시겠습니까? |
| --- | --- | --- |
| `.tex` | 원본 문서 및 장 | 예 |
| `.bib` | 참고문헌 데이터베이스 | 예(또는 Zotero에서 내보내기) |
| `.cls` | 문서 클래스 | 드물게 공급업체 템플릿 |
| `.sty` | 패키지/스타일 파일 | 자신만의 매크로를 작성할 때 |
| `.bst` | BibTeX 스타일 | 드물게 |
| `.aux` | 상호 참조 데이터 | **아니요:** 생성됨 |
| `.log` | 컴파일러 로그 | 디버깅 시 읽기 |
| `.pdf` | 출력 | 보기/제출 |

## 확장 가능한 프로젝트 레이아웃

```text
paper/
 main.tex
 chapters/
 figures/
 refs.bib
```

최상위 수준에 있는 하나의 `main.tex`는 진입점 역할을 하고, 장은 자체 폴더에 있으며 `\input` 또는 `\include`로 가져오고, 이미지는 `Figures/`에 있고 참고 문헌은 하나의 `refs.bib`에 유지됩니다. 이 레이아웃은 프로젝트가 4페이지 분량의 논문이든 논문이든 관리하기 쉽게 유지됩니다. [챕터 파일 분할](/learn/split-chapter-files/)은 조각이 연결되는 방식을 보여줍니다.

Git을 사용하는 경우 `*.aux`, `*.log` 및 기타 생성된 파일을 `.gitignore`에 추가하여 기록이 실제 소스만 추적하도록 하세요. Oleafly 프로젝트는 디스크의 일반 폴더이므로 이 조언은 변경되지 않고 적용됩니다. 가장 흔한 실수는 그 반대입니다. 이상한 컴파일 오류를 찾는 동안 '.aux' 파일을 삭제하면 해결되는 경우가 많습니다. 왜냐하면 잘못된 실행으로 인해 오래된 파일이 이후의 모든 컴파일을 손상시킬 수 있기 때문입니다.
