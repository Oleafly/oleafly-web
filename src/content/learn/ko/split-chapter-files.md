# 하나의 루트 파일, 많은 챕터

단일 `.tex` 파일에 있는 논문은 두 번째 장 부근에서 작업하기가 비참해집니다. 스크롤링이 생각을 대체하고 모든 컴파일이 모든 것을 처리합니다. 표준 치료법은 각 장이 자체 파일에 있는 클래스와 서문을 포함하는 하나의 루트 파일입니다. 루트 파일은 이들을 하나로 연결합니다.

## 루트 파일

```latex
% main.tex
\documentclass{report}
\begin{document}
\include{chapters/intro}
\include{chapters/methods}
\include{chapters/results}
\end{document}
```

`main.tex`는 당신이 컴파일한 유일한 파일입니다. 각 `\include`는 모든 플랫폼에서 슬래시를 사용하여 `.tex` 확장자 없이 다른 파일의 이름을 지정하고 해당 지점에서 해당 내용을 가져옵니다. 챕터 파일 자체에는 일반적으로 `\chapter{...}`로 시작하는 콘텐츠만 포함됩니다. 문서가 아니라 이 문서의 일부이기 때문에 `\documentclass`나 자체 `document` 환경이 없습니다.

## 포함 대 입력

두 가지 포함 명령은 다르게 동작하며 차이점에 따라 어느 명령을 사용할지 결정됩니다. `\include`는 장에 적합한 자료 ​​앞에 새 페이지를 시작하고 포함된 각 파일에 대해 별도의 `.aux` 파일을 작성하므로 선택적 컴파일이 가능합니다. `\input`은 일반 텍스트 붙여넣기입니다. 페이지 나누기가 없고 별도의 `.aux`가 없으며 다른 입력 내에 중첩될 수 있습니다. 따라서 `\input`은 자체 파일에 보관된 큰 테이블이나 공유 [매크로 파일](/learn/custom-commands/)과 같이 장보다 작은 조각에 적합한 도구입니다. 기억해야 할 한 가지 구조적 규칙은 `\include`는 포함된 파일 내에 중첩될 수 없지만 `\input`은 어디에서나 사용할 수 있다는 것입니다.

## 한 번에 한 장씩 초안 작성

```latex
\includeonly{chapters/methods}
```

프리앰블에 있는 `\includeonly`는 LaTeX에게 나열된 파일만 처리하는 동시에 다른 모든 파일의 저장된 `.aux` 데이터를 읽도록 지시합니다. 컴파일 속도가 극적으로 빨라지고, 다른 장의 레이블과 페이지 수가 해당 '.aux' 파일에서 재생되기 때문에 초안을 작성 중인 장의 상호 참조 및 번호 매기기가 올바르게 유지됩니다. 후반부는 다른 장을 완전히 잊어버리고 모든 `\ref`를 `??`로 바꾸는 `\include` 줄을 주석 처리하는 것보다 이것을 선호하는 이유입니다.

전체 빌드의 경우 `\includeonly` 줄에 주석을 달고 PDF를 공유하기 전에 항상 전체 컴파일을 실행하세요. 오래된 `.aux` 데이터는 제외된 챕터에서 편집한 내용보다 뒤처질 수 있기 때문입니다. 결과 폴더의 어떤 파일이 귀하의 것이고 어떤 파일이 생성되었는지는 [실제 프로젝트의 파일](/learn/latex-file-types/)을 참조하세요.
