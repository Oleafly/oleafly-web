# Oleafly 内部助理

Oleafly 包含一个人工智能助手，它可以在您的项目中工作，而不是在单独的聊天窗口中工作。与将 LaTeX 粘贴到一般聊天机器人中不同，它在您自己的 API 密钥上运行，可以读取正在编辑的项目，并在触摸文件之前显示每个建议的更改以供批准。

## 您的密钥，您的提供商

助手不会通过 Oleafly 的服务器进行模型调用。您可以为九个受支持的托管提供商之一提供 API 密钥，或者将应用程序指向本地 Ollama 安装并使用在您自己的硬件上运行的模型。请求根据该提供商的条款从您的计算机发送到您配置的提供商，并且您直接按照提供商的费率向其付款。 [AI 设置](/docs/ai-setup/) 中介绍了选择哪种模型以及如何设置密钥或 Ollama。

## 助手可以看到什么

当您提出问题或请求编辑时，助手会根据您的项目地图进行工作，并读取与请求相关的文件，例如您正在编辑的章节、定义宏的序言或引文问题后面的“.bib”文件。该上下文就是为什么它可以回答有关实际图 3 的“为什么图 3 浮动到下一页”，以及为什么它的编辑往往与您的文档已使用的符号和命令相匹配。

## 编辑您评论的内容，而不是刚刚发生的编辑

助手永远不会直接写入您的文件。它建议将更改作为差异，删除的行为红色，添加的行为绿色，您接受或拒绝每一项。在应用任何已接受的更改之前，Oleafly 会记录一个 Git 检查点，因此编辑之前的状态在 [Git 历史记录](/docs/git-history/) 中始终是一步之遥。删除文件是单独处理的，并且始终需要您的明确确认，无论助手正在做什么。

## 使用编译器关闭循环

因为助手住在构建旁边，所以它可以检查自己的工作。编辑后，它可以触发编译，读取日志，如果更改是为了修复错误，请检查该错误是否消失。它还可以读取已编译 PDF 的文本，因此可以确认请求的更改确实显示在输出中。模型仍然会产生错误的 LaTeX，因此请阅读您接受的内容。好处是，损坏的建议往往会在循环中被捕获并纠正，而不是稍后由您纠正。

日常机制位于 [chat](/docs/ai-chat/) 和 [inline edit](/docs/ai-inline-edit/) 文档中，而 [Oleafly 写作一周](/learn/oleafly-workflow/) 显示了助手在完整写作循环中的位置。
