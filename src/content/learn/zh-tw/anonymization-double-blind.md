# 雙盲做得對

雙盲審查意味著審查者不知道論文是誰寫的。出現錯誤是少數可能導致論文在未被閱讀的情況下被拒絕的格式錯誤之一，因此請將匿名化視為一個清單，而不是一種氛圍。

## 必須去的東西

|專案 |該怎麼辦 |
|---|---|
|作者姓名與隸屬關係 |刪除或替換為「匿名作者」|
|致謝 |刪除提交（資助者和同事識別您的身分）|
|回購協議和項目鏈接 |替換為匿名鏈接，請參見下文 |
|機構特定詳細資料 | “我們大學的集群”擊敗“斯坦福GPU集群” |
| 「我們之前的工作」措詞|以第三人稱重寫，見下文 |
|標誌、浮水印、標題 |刪除任何帶有團體或實驗室名稱的內容 |

許多類自動化第一行。對於 ACM 的課程，這是一種選擇：

```latex
\documentclass[sigconf,review,anonymous]{acmart}
```

其他場地提供了其模板的提交變體。 [IEEEtran](/learn/ieee-format-in-practice/) 場所通常只是告訴您省略作者區塊。

## 引用自己的作品

規則很簡單：像引用陌生人一樣引用自己。

錯誤：“在我們之前的工作 [7] 中，我們展示了…”
右：“Lovelace 等人 [7] 表明…”

不要遺漏你自己的相關論文。审稿人希望引用明显的相关工作，而可疑的空白可以像名字一样有效地使您去匿名化。唯一的例外是真正未发表的作品，您可以将其作为匿名补充材料上传。

## 匿名工件

審閱者越來越期望程式碼和資料。 GitHub 連結具有放射性：用戶名就在那裡。有效的選項：

- 為此建造的服務（anonymous.4open.science 是現場標準）
- 一次性帳戶下的新儲存庫，具有已刪除的提交記錄
- 隨提交一起上傳的補充 zip，從文件頭和筆記本中刪除了作者姓名

上傳前檢查 zip：許可證檔案、「作者」、筆記本元資料和硬編碼的主目錄路徑 (“/home/ada/...”) 所有洩漏名稱。

## 背叛你的意外

紙本文字是匿名的，但 PDF 可能不是：

- **PDF 元數據。 ** 作者欄位通常會從您的系統自動填入。檢查“pdfinfo”或檢視器的文件屬性，並透過“\hypersetup{pdfauthor={}}”清除它。
- **檔名。 ** `lovelace-sigconf-final.pdf` 撤銷所有內容。將其命名為“paper.pdf”或提交編號。
- **圖源。 ** 從工具匯出的圖表可以將使用者名稱嵌入元資料或螢幕截圖中的可見路徑中。
- **預印本。 ** 在提交之前發佈到 arXiv 在許多場所是允許的，但在其他場所是禁止的。 CFP 說了算。閱讀它。這是[選擇場地的一部分](/learn/choose-your-venue/)。

## 相機就緒後翻轉回來

接受後，一切都會返回：名稱、從屬關係、致謝、真正的存儲庫連結以及第一人稱措辭（如果您喜歡）。預算一個小時的去匿名化通行證。它所涉及的地方比你記得的還要多，[相機準備清單](/learn/first-paper-roadmap/) 是抓住掉隊者的時刻。
