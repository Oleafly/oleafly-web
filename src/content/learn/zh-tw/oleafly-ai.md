# Oleafly 內部助理

Oleafly 包含一個人工智慧助手，它可以在您的專案中工作，而不是在單獨的聊天視窗中工作。與將 LaTeX 貼到一般聊天機器人中不同，它在您自己的 API 金鑰上運行，可以讀取正在編輯的項目，並在觸摸文件之前顯示每個建議的更改以供批准。

## 您的金鑰，您的提供者

助手不會透過 Oleafly 的伺服器進行模型呼叫。您可以為九個受支援的託管提供者之一提供 API 金鑰，或將應用程式指向本機 Ollama 安裝並使用在您自己的硬體上執行的模型。請求根據該提供者的條款從您的電腦發送到您配置的提供者，並且您直接按照提供者的費率向其付款。 [AI 設定](/docs/ai-setup/) 中介紹了選擇哪種模型以及如何設定金鑰或 Ollama。

## 助理可以看到什麼

當您提出問題或要求編輯時，助手會根據您的專案地圖進行工作，並讀取與請求相關的文件，例如您正在編輯的章節、定義巨集的序言或引文問題後面的「.bib」文件。該上下文就是為什麼它可以回答有關實際圖 3 的“為什麼圖 3 浮動到下一頁”，以及為什麼它的編輯往往與您的文件已使用的符號和命令相符。

## 編輯您評論的內容，而不是剛剛發生的編輯

助手永遠不會直接寫入您的文件。它建議將更改作為差異，刪除的行為紅色，添加的行為綠色，您接受或拒絕每一項。在套用任何已接受的變更之前，Oleafly 會記錄一個 Git 檢查點，因此編輯先前的狀態在 [Git 歷史記錄](/docs/git-history/) 中始終是一步之遙。刪除文件是單獨處理的，並且始終需要您的明確確認，無論助手正在做什麼。

## 使用編譯器關閉循環

因為助手住在建造旁邊，所以它可以檢查自己的工作。編輯後，它可以觸發編譯，讀取日誌，如果更改是為了修復錯誤，請檢查該錯誤是否消失。它還可以讀取已編譯 PDF 的文本，因此可以確認請求的變更確實顯示在輸出中。模型仍然會產生錯誤的 LaTeX，因此請閱讀您接受的內容。好處是，損壞的建議往往會在循環中被捕獲並糾正，而不是稍後由您糾正。

日常機制位於 [chat](/docs/ai-chat/) 和 [inline edit](/docs/ai-inline-edit/) 文件中，而 [Oleafly 寫作一周](/learn/oleafly-workflow/) 顯示了助手在完整寫作循環中的位置。
