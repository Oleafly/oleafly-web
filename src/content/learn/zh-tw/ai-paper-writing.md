# 保持誠實的草稿幫助

語言模型是現在撰寫的許多論文的一部分。有用的問題是在哪裡劃清界線。模型可以幫助您更清楚地表達您所知道的內容。不能相信它會為你了解事情。幫助措辭可以節省時間，風險很小。讓模型發明事實或來源會將捏造的材料以您的名義記錄在學術記錄中。

## 模型真正有幫助的地方

結構工作是最好的利用。給定您的摘要和章節列表，模型可以建議不同的順序，注意您的貢獻隱藏在第 5 節中，或者猜測持懷疑態度的審稿人會問什麼。你可以根據你對工作已有的了解來判斷每一個建議。壓縮的工作原理是一樣的：交出你自己在十篇相關論文上的粗略筆記，並要求一個更緊湊的段落。事實歸你所有；模型執行句子木工。對你所寫的散文進行清晰的編輯是常見的情況。縮短、理清和刪除你自己的段落中的行話是工作模型做得很好的方法，而且你仍然可以決定其含義是否得以保留。

## 模型出現危險故障的地方

永遠不要讓模型提供引用。當要求提供參考資料時，模型會產生看起來合理的條目，其中包含真實的地點、聽起來真實的作者以及發明的標題或 DOI。它們產生引文的樣子，而不是檢索存在的內容。每一份參考文獻都必須是您自己找到並與實際論文進行核對的。 [建構持久的 .bib](/learn/create-bibliography/) 涵蓋保持資料庫健全。同樣警惕技術內容。要求「填寫推導」的模型將產生可能有細微錯誤的自信步驟，而您無法發現的錯誤就無法發布。也不要提交你沒有仔細閱讀過的散文。示範文本可能會夾雜一些誇張的說法和小的事實錯誤，一旦提交，每句話都是你的。

## 確保安全的護欄

將手稿保存在 Git 下，這樣每個模型輔助的更改都是可見的差異，您可以查看和恢復。 [將論文放在 GitHub 上](/learn/sync-with-github/) 顯示了設定。 Oleafly 的助手加入了自己的核准差異和預編輯檢查點，如[Oleafly 內部的助手](/learn/oleafly-ai/) 所述。也要檢查您場地的政策。許多期刊和會議現在都要求揭露人工智慧的協助，幾乎所有期刊和會議都要求作者對內容承擔全部責任，無論使用何種工具。經驗法則：僅在可以比您自己編寫的速度更快地驗證輸出的情況下使用該模型。其他的，自己寫吧。
