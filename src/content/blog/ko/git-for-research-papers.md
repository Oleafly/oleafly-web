연구원들은 이미 코드에 Git을 사용하고 있습니다. 논문은 코드와 매우 비슷해 보입니다. 일반 텍스트,
포함하고 정크를 만듭니다. 원고를 저장소에 넣는 것은 그것보다 덜 이상합니다.
한 번 시도해 보면 소리가 납니다.

## 정크를 무시하세요

LaTeX를 위한 합리적인 `.gitignore`:

```text
*.aux
*.log
*.out
*.toc
*.synctex.gz
*.bbl
*.blg
*.fdb_latexmk
*.fls
```

`.tex`, `.bib`, 재생성할 수 없는 수치, 그리고 다음과 같은 경우 클래스 파일을 커밋합니다.
대학에서는 그것을 요구합니다. 저널이 원하지 않는 한 모든 PDF 커밋을 건너뛰세요.
아카이브의 바이너리.

편집자가 Git을 시작하면 빌드 캐시와 PDF가 있는지 확인하세요.
중간체는 무시됩니다. 보조 파일에서 발생하는 빈 "노이즈" 커밋 스트림
로그를 쓸모 없게 만듭니다. 당신이 그것을 읽는 것을 멈추면 역사가 도움이 될 수 없습니다
뭔가 고장났을 때 당신.

## 라인이 아닌 자체 파일

같은 문단에 두 사람이 합체하는 아픔이다. 장이나 섹션을 선호하세요
소유권. 그룹이 검토할 수 있을 만큼 큰 경우 풀 요청을 사용하세요.
실제로 도움이 됩니다.

하나의 버퍼에서 실시간 다중 사용자 타이핑은 다른 도구입니다(브라우저 LaTeX
편집자). Git 협업은 분기, 푸시, 검토 등 더 느리고 더 명확합니다.
종이 흔적이 필요할 때 잘 작동합니다. 세 사람이 입력해야 하는 경우
오늘 오후에 함께 추상화하고 다른 것을 선택하세요.

## 나중에 읽을 수 있는 메시지 커밋

"문제 수정"은 3개월이 지나면 쓸모가 없습니다. "트랜스포머 관련 작업 다시 작성"
충분하다. 두 개의 레이어가 도움이 됩니다:

1. 귀하가 지정한 마일스톤: 섹션 초안, 제출, 카메라 준비.
2. 안전 체크포인트: 스냅샷을 자주 찍어 나쁜 오후를 되돌릴 수 있습니다.

컴파일이 성공한 후 또는 입력을 중단한 후 편집기에서 체크포인트가 발생하는 경우,
그것들을 유일한 역사가 아닌 바닥으로 취급하십시오. 다음과 같은 경우 실제 메시지를 작성하세요.
섹션 토지 또는 초안은 공동저자에게 전달됩니다.

## 개인 리모콘

게시되지 않은 작업은 비공개 GitHub 또는 GitLab 프로젝트에 속합니다. 졸업과
실험실 이동은 사람들이 임의의 클라우드 편집자 계정에 액세스할 수 없게 되는 경우입니다. 리모콘
당신이 제어하는 것은 백업입니다.

네트워크가 있을 때 푸시하세요. 마감일 전날 밤까지 기다리지 마십시오.
리모컨이 연결되지 않았음을 발견합니다.

## 로컬 컴파일, 원격 백업

대부분의 경우 루프는 다음과 같습니다. 오프라인으로 편집 및 컴파일하고,
네트워크를 가지고 있습니다. 단지 입력을 위해 라이브 브라우저 세션이 필요하지 않습니다.

툴링에서 원하는 것:

- 모든 프로젝트는 이미 실제 Git 저장소입니다('git init'을 잊어버리지 마세요).
- 성공적인 컴파일 및 유휴 편집 후 자동 체크포인트
- 동일한 앱에서 단계, 병렬 비교, 삭제 및 원클릭 복원
  편집기와 PDF
- 원격용 GitHub는 선택 사항입니다. 기록은 이미 디스크에서 작동합니다.
- 병렬 실험을 위해 전체 기록이 포함된 전체 프로젝트를 분기합니다(위험
  방법 재작성, 대체 재개) 제출 사본이 그대로 유지되는 동안
- AI 편집을 활성화하면 먼저 체크포인트를 통과하고 착륙을 통해서만 착륙합니다.
  승인 차이

[Oleafly](https://github.com/Oleafly/Oleafly/releases/latest)는 다음과 같이 구축되었습니다.
방법: 일반 폴더, 실제 `.git`, 파일 이름을 지정하는 자동 체크포인트
이동됨, 편집 가능한 작업 트리 차이점이 있는 소스 제어 패널, 이후 복원
확인, 선택적 GitHub 게시/푸시/당기기(앞/뒤), 프로젝트 포크
도서관의 계보. 터미널 `git log`는 앱과 일치합니다.
동일한 저장소. AI 체크포인트를 사용하면 동일한 지점에 도착합니다.
복원한 기록입니다.

신중한 습관과 별도의 Git을 사용하여 이 부분을 대략적으로 추정할 수 있습니다.
클라이언트. 차이점은 역사가 당신이 설정하고 기억하는 것인지,
또는 연구 작업 공간이 첫날 SyncTeX 옆에서 가정하고
컴파일.

## Git이 해결하지 못하는 것

Git은 PDF만 여는 PI의 주석을 대체하지 않으며,
누구의 초록이 맞는지 결정하세요. 이진수는 여전히 잘 병합되지 않으므로 계속 유지하십시오.
규모가 작고 재생성할 수 있는 토지를 선호하며 조기에 소유권에 동의합니다.

Git을 거부하는 공동저자의 경우 검토를 위해 PDF 또는 DOCX를 내보내고 '.tex'를 다음과 같이 유지하세요.
진실의 근원. 참조
[Word만 사용하는 공동저자](/learn/collaborator-uses-word/).

## 최소한의 실천

1. 전체 경력에 대해 하나의 메가 레포가 아닌 논문 또는 논문당 하나의 레포를 사용하세요.
2. 첫날에 정크 빌드를 위한 `.gitignore`.
3. 2인 이상이 편집하는 경우 챕터 소유권.
4. 마일스톤은 읽을 수 있는 메시지로 커밋됩니다.
5. 업무 전 개인 리모콘을 연결해 두는 것이 중요합니다.
6. 복원 테스트는 일부러 한 번만 하므로 첫 번째 응급 상황이 첫 번째가 아닙니다.
   복원.

해당 목록을 고수하면 논문용 Git은 대부분
배경입니다. 두 번째 취미가 아닌 마감일 이전에 지루한 신뢰성을 원합니다.
