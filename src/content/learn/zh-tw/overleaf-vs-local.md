# 瀏覽器項目與磁碟上的資料夾

當您開始編寫 LaTeX 時，您面臨一個早期決定：您的專案是位於其他人伺服器上的瀏覽器標籤中，還是位於您自己磁碟上的資料夾中？兩種模型產生相同的 PDF。它們的不同之處在於誰擁有原始程式碼、網路中斷時會發生什麼以及您控制了多少周圍的工具鏈。

## 每個模型為您提供什麼

| |雲端（例如背頁）|本地（Oleafly、TeX Live）|
| --- | --- | --- |
|設定 |即時，無需安裝 |一次安裝 |
|離線 |有限公司|編輯總是有效的；使用緩存的包編譯運行|
|隱私權 |供應商儲存您的專案 |檔案保留在您的磁碟上 |
| git | git透過同步橋| Native，資料夾中的真實儲存庫 |
|合作|即時遊標 | Git、補丁、共享資料夾 |
|成本|免費套餐加訂閱 |免費|

雲端項目是服務為您呈現的資料庫中的一行。本機專案是一個目錄，您可以在檔案總管中開啟、複製到 USB 隨身碟、使用任何工具搜尋以及使用普通 Git 版本。這種差異聽起來很抽象，直到最後期限恰逢停電、付費專區變更或航班起飛。

## 當雲端是正確的選擇時

即時共同編輯是雲端的真正優勢。如果三位合著者需要在截止日期前的最後一小時內輸入同一段落，並且他們都不會安裝軟體，那麼瀏覽器編輯器就是實際的答案。目前沒有任何本地內容可以取代同時遊標。

## 當本地是正確的選擇時

當草稿敏感或未發佈時，當您在飛機或受限網路上工作時，當您的數字和數據很大時，或者當您想要不依賴訂閱層的版本歷史記錄時，本地獲勝。無論明天是否存在任何服務，本地 Git 儲存庫都會記錄您的更改，並且相同資料夾可與終端、程式碼編輯器或協作者的克隆一起使用。

Oleafly 是為此表的本地端建構的：編譯器在應用程式內部提供，專案是具有真實 Git 歷史記錄的普通資料夾，並且可選的 AI 使用您自己的金鑰運行。較長的比較位於 [博客](/blog/local-first-vs-cloud-latex-editors/)，文件涵蓋了 [這兩個模型如何協同工作](/docs/why-oleafly/) 通過 GitHub。
