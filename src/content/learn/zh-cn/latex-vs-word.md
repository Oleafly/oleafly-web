# 当 LaTeX 打败 Word 时（以及当它没有打败 Word 时）

这两种工具都不是普遍更好。文字处理器针对直接操作进行了优化：您看到的就是文档。 LaTeX 优化结构：您以纯文本描述文档，然后编译器对其进行排版。哪种模式获胜取决于您面前的文件，而不是部落忠诚度。

## LaTeX 的学习曲线在哪里

方程是最清楚的情况。 Word 的方程式编辑器适用于家庭作业问题。跨越一百个带有交叉引用的编号方程变得很痛苦。在 LaTeX 中，无论您重新组织多少，“\label”和“\ref”都会保持每个数字的正确性，[交叉引用](/learn/cross-references/) 课程详细介绍了这一点。

长结构化文档的行为方式相同。包含单独文件中的章节、自动目录和一致的标题样式的论文在 LaTeX 中很常见，但在文字处理程序中却很脆弱。引文遵循相同的模式：包含数百个条目的 BibTeX 数据库会针对任何期刊风格重新格式化，而手工维护的参考文献列表会很快退化。有关机制，请参阅[添加引用](/learn/add-itations/)。

随着时间的推移，两个更安静的优势会复合。 LaTeX 源代码是纯文本，因此 Git 可以清晰地比较和版本化它，并且相同的源代码在几年后在任何机器上生成相同的 PDF，没有布局漂移。

## Word 或 Google Docs 是正确的选择

当协作是文档时，直接操作的编辑会获胜。如果您的共同作者不是技术人员，只从事跟踪更改，并且需要在今天下午发表评论，那么共享文档就是实际的答案。他们还赢得了简短的一次性信件，其中 LaTeX 设置成本高于排版回报，以及只接受“.docx”文件的出版商或人力资源部门。

## 实用的混合体

将真实来源保留在 LaTeX 中，并为需要的人导出草稿。 PDF收集评论； Pandoc 生成的 DOCX 满足“.docx”要求。这些回合的决定会合并回“.tex”文件，该文件仍然是规范版本。关于[与基于 Word 的协作者合作](/learn/collaborator-uses-word/) 的课程将介绍这个循环。

## 简短的回答

使用 LaTeX 处理您在几个月内要引用、编号、交叉引用或修改的任何内容。当 LaTeX 的社会成本超过其排版优势时，请使用文字处理器。这两种判断都是合理的，并且大多数研究人员在特定年份使用这两种工具。
