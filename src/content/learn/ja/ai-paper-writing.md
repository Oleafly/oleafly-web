# 正直さを保つドラフトヘルプ

言語モデルは、現在書かれている論文の数の一部です。有益な質問は、どこに線を引くかということです。モデルは、自分が知っていることをより明確に伝えるのに役立ちます。あなたに代わって物事を知ることは信頼できません。言葉遣いを手伝ってもらうと、リスクはほとんどなく時間を節約できます。モデルに事実や情報源をでっち上げさせると、捏造された資料があなたの名前で学術記録に載せられます。

## モデルが真に役立つ場所

構造工事が最適な用途です。要約とセクションのリストが与えられると、モデルは異なる順序を提案したり、自分の貢献がセクション 5 に埋もれていることに気づいたり、懐疑的な査読者が何を質問するかを推測したりすることができます。すべての提案を、その作品についてすでに知っていることに照らして判断できます。圧縮も同様に行われます。10 冊の関連論文に関する自分の大まかなメモを渡し、よりタイトな段落を要求します。事実はあなたのもののままです。モデルは文章の大工仕事をします。あなたが書いた散文をわかりやすく編集することは日常茶飯事です。自分の段落の専門用語を短くし、解きほぐし、カットすることはうまくいく作業モデルですが、それでも意味が生き残るかどうかを判断するのはあなたです。

## モデルが危険なほど失敗する場合

モデルに引用を提供させないでください。参考資料を求められると、モデルは実際の会場、本物のような著者、発明されたタイトルや DOI を使用して、もっともらしく見えるエントリを作成します。存在するものを取得するのではなく、引用がどのようなものかを生成します。すべての参考文献は、自分で見つけて実際の論文と照合したものでなければなりません。 [長持ちする .bib を作成する](/learn/create-bibliography/) では、データベースの健全性を維持することがカバーされています。技術的な内容にも同様に注意してください。 「導出を埋める」よう求められたモデルは、微妙に間違っている可能性がある自信に満ちたステップを生成します。また、検出できないエラーは公開できないものです。よく読んでいない散文も決して投稿しないでください。モデルテキストには過剰請求や小さな事実伝票を密かに持ち込むことができ、一度送信すると、すべての文があなたのものになります。

## これを安全にするガードレール

原稿を Git の下に保存しておくと、モデルを利用したすべての変更が目に見える差分として表示され、確認して元に戻すことができます。 [論文を GitHub に置く](/learn/sync-with-github/) にセットアップを示します。 Oleafly のアシスタントは、[Oleafly 内のアシスタント](/learn/oleafly-ai/) で説明されているように、独自の承認差分と編集前チェックポイントを追加します。会場のポリシーも確認してください。現在、多くのジャーナルやカンファレンスでは AI 支援の開示が求められており、ほぼすべてのジャーナルやカンファレンスが、ツールに関係なくコンテンツに対する全責任を著者に負わせています。経験則: 自分で作成するよりも早く出力を検証できる場合にのみモデルを使用してください。それ以外はすべて自分で書きます。
