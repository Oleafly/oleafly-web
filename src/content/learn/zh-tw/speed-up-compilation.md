# 縮短 PDF 等待時間

一篇需要九十秒完成的论文会改变你的写作方式。在進行小幅編輯後，您會停止重新編譯，錯誤會堆積起來，看不見，而使 LaTeX 令人愉悅的回饋循環也消失了。在优化之前，先了解时间都花在哪里了。在大多数长文档中，主导构建的不是包的数量，而是少量的重资产，尤其是大图像和复杂的 TikZ 图片。下面的技術直接攻擊這些。

## 起草時跳過數字

「draft」選項使 LaTeX 以相同大小的空白方塊替換每個圖像，這在跳過圖像處理的同時保留了佈局和分頁符號：

```latex
\documentclass[draft]{article}
```

類級別的「草稿」也用黑條標記過滿的線條，有些人覺得很有用，而有些人則覺得很吵。要將效果限制在圖像上，請將選項傳遞給包，如 `\usepackage[draft]{graphicx}`，或使用 `\includegraphics[draft]{...}` 傳遞給單一罪魁禍首。請記住在共享 PDF 之前將其刪除，因為對於不知道該選項的人來說，草稿版本看起來很糟糕。與草稿模式無關，按[放入圖形](/learn/insert-images/)中所述，縮小一次巨大的照片，因為 40 MB 的圖像會在每次編譯時永遠花費您的費用。

## 只編譯目前章節

如果您的章節位於使用“\include”拉入的單獨檔案中，則“\includeonly”命令將建置限制為您命名的檔案：

```latex
\includeonly{chapters/04-results}
```

將其放在序言中，LaTeX 會在閱讀其他文件的「.aux」文件的同時編譯該章，因此文件其餘部分的頁碼和交叉引用大致保持正確。這是論文最大的節省，通常可以將一分鐘的建造時間縮短為幾秒鐘。它僅適用於“\include”，不適用於“\input”，這是按照[將文件拆分為文件](/learn/split-chapter-files/)中所述構造長文檔的原因之一。

## 快取昂貴的圖片

TikZ 圖片在每次編譯時都會從頭開始重新繪製。 “external”庫載入了“\usetikzlibrary{external}”和“\tikzexternalize”，將每張圖片編譯為其自己的 PDF 一次，並重複使用它，直到程式碼變更。該設置具有銳利的邊緣，並且將大圖片移動到獨立文件中的手動替代方案也同樣有效；兩者都包含在[獨立 TikZ 到 PDF 或 PNG](/learn/tikz-export/) 中。

## 更少的傳球次數，更快的鐵桿

參考書目和交叉引用解析需要多次傳遞，但在起草散文時，您很少需要它們，因此一次快速傳遞就足夠了，完整的序列可以等到您檢查參考文獻為止。硬體和位置也很重要：本地引擎在您自己的 CPU 上編譯，無需上傳或佇列，這就是 Oleafly 運行建置的方式。

將“\includeonly”和草圖一起應用，即使是一篇大型論文通常也會在幾秒鐘內返回，這是您在每個段落之後再次開始重新編譯的時間點。
