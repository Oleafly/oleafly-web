# 브라우저 프로젝트와 디스크의 폴더

LaTeX 작성을 시작하면 초기 결정에 직면하게 됩니다. 프로젝트가 다른 사람 서버의 브라우저 탭에 있습니까, 아니면 자신의 디스크에 있는 폴더에 있습니까? 두 모델 모두 동일한 PDF를 생성합니다. 소스를 보유하는 사람, 네트워크가 중단되면 어떤 일이 발생하는지, 주변 툴체인을 얼마나 제어하는지가 다릅니다.

## 각 모델이 제공하는 기능

| | 클라우드(예: Overleaf) | 로컬(Oleafly, TeX Live) |
| --- | --- | --- |
| 설정 | 즉시, 설치할 것이 없음 | 한 번의 설치 |
| 오프라인 | 한정 | 편집은 항상 가능합니다. 캐시된 패키지로 실행되는 컴파일 |
| 개인정보 보호 | 공급자는 귀하의 프로젝트를 저장합니다 | 파일은 디스크에 남아 있습니다 |
| 힘내 | 동기화 브리지를 통해 | 네이티브, 폴더의 실제 저장소 |
| 협업 | 실시간 커서 | 힘내, 패치, 공유 폴더 |
| 비용 | 무료 등급 및 구독 | 무료 |

클라우드 프로젝트는 서비스가 사용자를 위해 렌더링하는 데이터베이스의 행입니다. 로컬 프로젝트는 파일 관리자에서 열고, USB 드라이브에 복사하고, 어떤 도구로든 검색하고, 일반 Git으로 버전을 지정할 수 있는 디렉터리입니다. 마감일이 서비스 중단, 페이월 변경 또는 비행과 일치할 때까지 이러한 차이는 추상적으로 들립니다.

## 클라우드가 올바른 선택인 경우

실시간 공동 편집은 클라우드의 진정한 장점입니다. 세 명의 공동 저자가 마감일 전 마지막 한 시간 동안 동일한 문단을 입력해야 하는데 그들 중 누구도 소프트웨어를 설치하지 않을 경우 브라우저 편집기가 실용적인 답입니다. 현재 로컬 커서는 동시 커서를 대체하지 않습니다.

## 로컬이 올바른 선택일 때

초안이 민감하거나 게시되지 않은 경우, 비행기나 제한된 네트워크에서 작업하는 경우, 수치와 데이터가 큰 경우 또는 구독 계층에 의존하지 않는 버전 기록을 원하는 경우 로컬이 승리합니다. 로컬 Git 저장소는 내일 서비스가 존재하는지 여부에 관계없이 변경 사항을 기록하며 동일한 폴더가 터미널, 코드 편집기 또는 공동 작업자의 복제본과 함께 작동합니다.

Oleafly는 이 테이블의 로컬 측면을 위해 구축되었습니다. 컴파일러는 앱 내부에 제공되고, 프로젝트는 실제 Git 기록이 있는 일반 폴더이며, 선택적 AI는 자체 키로 실행됩니다. 더 자세한 비교 내용은 [블로그](/blog/local-first-vs-cloud-latex-editors/)에 있으며 문서에서는 GitHub를 통해 [두 모델이 함께 작동하는 방법](/docs/why-oleafly/)을 다룹니다.
