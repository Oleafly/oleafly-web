# 실시간 커서가 없는 공동 작성

공동 저자의 커서 이동을 볼 수 있는 실시간 공동 편집은 모델 클라우드 편집자가 판매하는 것입니다. 그것 없이도 좋은 논문이 많이 쓰여졌습니다. 작성자가 로컬에서 작업할 때 Git을 기반으로 구축된 비동기식 협업은 신뢰할 수 있는 패턴입니다. 각 사람은 자신의 컴퓨터에서 편집하고 변경 사항은 문자별로가 아니라 의도적으로 병합됩니다. 약간 더 많은 조정이 필요하며 오프라인 작업, 전체 기록 및 다른 사람의 서버에 대한 종속성이 없어 보답합니다.

## Git을 백본으로 사용

표준 설정은 일반적으로 모든 사람이 가져오고 푸시하는 GitHub의 공유 저장소입니다. 각 작성자는 최신 상태 가져오기, 쓰기, 커밋, 푸시 등 세션에서 작업합니다. LaTeX는 일반 텍스트이기 때문에 Git은 병렬 변경 사항을 문서의 다른 부분에 자동으로 병합하며 설정에는 몇 분 정도 걸립니다. [GitHub에 논문 게재](/learn/sync-with-github/)가 이를 다루고 있습니다. 한 공동 작업자가 Git 호스트를 사용할 수 없거나 사용하지 않을 경우 패치가 공백을 메웁니다. 'git format-patch'는 커밋을 이메일로 보낼 수 있는 작은 파일로 변환하고 수신자는 이를 'git am'으로 적용하여 저작자와 기록을 그대로 유지합니다. 이는 오래된 작업 흐름이며 이메일이 지원되는 모든 곳에서 여전히 작동합니다.

하이브리드는 공동 작성자가 동기화된 폴더를 요구할 때도 작동합니다. 편의를 위해 공유 복사본을 Dropbox 또는 Syncthing에 보관하지만 한 사람이 Git 기록을 유지하고 병합을 수행하도록 합니다. 두 사람의 실시간 Git 체크아웃이 동일한 동기화 폴더를 가리키지 않도록 하세요. '.git' 디렉터리 내에서 동기화 충돌로 인해 저장소가 손상되기 때문입니다.

## 문서를 파일별로 나누기

사람들이 동일한 파일을 거의 만지지 않으면 병합이 거의 발생하지 않습니다. 각 장이나 섹션이 자체 파일에 있도록 원고를 분할하고 `\input{chapters/methods}`를 사용하여 얇은 `main.tex`에서 가져온 것입니다. 메커니즘은 [문서를 파일로 분할](/learn/split-chapter-files/)에 있습니다. 그런 다음 소유권을 할당합니다. 각 공동저자는 자신의 파일에 초안을 작성하고 한 명의 통합자는 표기법과 어조의 일관성을 위해 서문, 병합 및 최종 읽기를 처리합니다. 이는 소프트웨어 팀이 서로 밟지 않는 방법을 반영하며 동일한 이유로 작동합니다.

## 실제로 무엇이 잘못됐는가?

피해야 할 실패 모드는 두 사람이 같은 시간에 같은 단락을 편집하는 것입니다. Git은 이를 충돌로 표시하고 LaTeX 충돌은 읽을 수 있지만 해결하기가 지루하므로 가장 저렴한 수정은 소셜입니다. "오늘 소개에 있습니다"라는 빠른 메시지로 거의 모든 문제를 방지할 수 있습니다. 두 가지 글쓰기 습관이 나머지를 줄입니다. 소스 라인당 하나의 문장을 유지하여 인접한 문장에 대한 병렬 편집이 전혀 충돌하지 않도록 하고, 각 쓰기 세션 직전에 끌어서 항상 최신 텍스트를 편집하도록 합니다.
