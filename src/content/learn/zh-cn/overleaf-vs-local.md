# 浏览器项目与磁盘上的文件夹

当您开始编写 LaTeX 时，您面临一个早期决定：您的项目是位于其他人服务器上的浏览器选项卡中，还是位于您自己磁盘上的文件夹中？两种模型生成相同的 PDF。它们的不同之处在于谁拥有源代码、网络中断时会发生什么以及您控制了多少周围的工具链。

## 每个模型为您提供什么

| |云（例如背页）|本地（Oleafly、TeX Live）|
| --- | --- | --- |
|设置 |即时，无需安装 |一次安装 |
|离线 |有限公司|编辑总是有效的；使用缓存的包编译运行|
|隐私 |提供商存储您的项目 |文件保留在您的磁盘上 |
| git | git通过同步桥| Native，文件夹中的真实存储库 |
|合作|实时光标 | Git、补丁、共享文件夹 |
|成本|免费套餐加订阅 |免费|

云项目是服务为您呈现的数据库中的一行。本地项目是一个目录，您可以在文件管理器中打开、复制到 USB 驱动器、使用任何工具搜索以及使用普通 Git 版本。这种差异听起来很抽象，直到最后期限恰逢停电、付费专区变更或航班起飞。

## 当云是正确的选择时

实时共同编辑是云的真正优势。如果三位合著者需要在截止日期前的最后一小时内输入同一段落，并且他们都不会安装软件，那么浏览器编辑器就是实际的答案。当前没有任何本地内容可以替代同时游标。

## 当本地是正确的选择时

当草稿敏感或未发布时，当您在飞机或受限网络上工作时，当您的数字和数据很大时，或者当您想要不依赖于订阅层的版本历史记录时，本地获胜。无论明天是否存在任何服务，本地 Git 存储库都会记录您的更改，并且同一文件夹可与终端、代码编辑器或协作者的克隆一起使用。

Oleafly 是为此表的本地端构建的：编译器在应用程序内部提供，项目是具有真实 Git 历史记录的普通文件夹，并且可选的 AI 使用您自己的密钥运行。较长的比较位于 [博客](/blog/local-first-vs-cloud-latex-editors/)，文档涵盖了 [这两个模型如何协同工作](/docs/why-oleafly/) 通过 GitHub。
