# 將論文放到 GitHub 上

LaTeX 手稿是純文本，這使其非常適合 Git。每個草稿都會成為您可以返回的提交，每個更改都作為行級差異可見，並且 GitHub 為您提供異地副本以及共同作者拉取當前狀態的方法。這些都不需要高級的 Git。一篇論文可能需要五個一致使用的命令。

## 初始設定

```bash
git init
# add a .gitignore for *.aux *.log *.out *.toc *.synctex.gz
git add main.tex refs.bib figures/
git commit -m "Initial manuscript"
gh repo create my-paper --private --source=. --push
```

在專案資料夾中運行一次。 「.gitignore」步驟比看起來更重要。每次編譯都會重新產生“.aux”、“.log”、“.out”、“.toc”和“.synctex.gz”文件，提交它們會將真正的更改隱藏在機器噪音下，並在共同作者之間產生毫無意義的合併衝突。僅追蹤您創作的內容：「.tex」來源、「.bib」資料庫、圖形以及場地提供給您的任何類別或樣式檔案。 PDF 也是一個建構產品。大多數團隊都會將其保留並在本地重建，儘管將其附加到標記版本是凍結已提交版本的合理方法。在作品公開之前，保持儲存庫的隱私。未發表的手稿不屬於索引。

## 讓合著者保持理智的習慣

讓每個提交都進行一項邏輯更改，例如「修訂第 3 節介紹」或「新增消融表」。然後，歷史就讀作報紙的故事，錯誤的編輯可以被恢復，而不會造成附帶損害。在開始寫作之前拉動，在停止時推動。合併衝突隨著分支分開的時間而增加。一旦合著者拉出共享分支，就永遠不要強行推送它：這會重寫他們腳下的歷史。將大型二進位工件（資料集、影片）保留在紙本儲存庫之外。連結到存檔或使用單獨的資料存儲庫。 Git 永遠儲存每個二進位檔案的每個版本。

LaTeX 特有的一個習慣是：每一源代碼行寫一個句子，使差異的可讀性顯著提高，因為單字編輯顯示為單行更改，而不是重排的段落。

## Oleafly 如何融入其中

每個 Oleafly 專案都是磁碟上的一個普通資料夾，因此這些命令無需更改即可對其進行操作。該應用程式還可以在每次成功編譯後自動建立 Git 提交，這為您的有意提交之間提供了細粒度的安全網。請參閱[Git 歷史記錄](/docs/git-history/)。有關在此基礎上建構的協作模式，包括補丁交換和章節所有權，請參閱[不使用即時遊標共同創作](/learn/offline-collaboration/)。
