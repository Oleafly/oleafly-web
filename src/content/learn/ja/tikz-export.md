# スタンドアロン TikZ を PDF または PNG に変換

TikZ 画像は通常、論文内に存在しますが、スライドデッキで再利用したり、Word で作業する共著者に渡したり、PNG が必要な場所にアップロードしたり、ドキュメントを作成するたびに高価な図面を再コンパイルすることを単に回避したりするために、図を独自のファイルとして必要とすることがよくあります。 「スタンドアロン」ドキュメント クラスはまさにこれのために存在します。画像のサイズに合わせて切り取られたページ上に 1 つの画像が植字されます。

```latex
\documentclass[tikz,border=2pt]{standalone}
\begin{document}
\begin{tikzpicture}
 \draw (0,0) -- (1,1);
\end{tikzpicture}
\end{document}
```

## クラスオプションの機能

`tikz` オプションは、TikZ パッケージをロードし、`tikzpicture` の周囲で出力ページをぴったりとトリミングするように `standalone` に指示します。そのため、結果として得られる PDF は図面とまったく同じ大きさで、ページ余白はありません。 `border=2pt` オプションは、すべての側面に 2 点のクッションを追加します。これにより、境界ボックス上に正確に位置するストロークがビューアやプリンタによって削られるのを防ぎます。このファイルを他のドキュメントと同様にコンパイルすると、図のみを含む小さく切り取られた PDF が出力されます。

PDF はベクターなので、ぼやけることなく任意のサイズに拡大縮小できます。 `\includegraphics` を使用して別のドキュメントにドロップすると、[グラフィックとしての PDF ページ](/learn/include-pdf-as-figure/) で説明されているように機能します。ラスター コピーが本当に必要な場合は、図面を再作成するのではなく、コンパイルされた PDF を変換します。 「pdftoppm -png -r 300 Figure.pdf Figure」などのコマンドライン ツールは 300 dpi の PNG を生成し、「pdf2svg」または Inkscape は SVG を生成します。 PNG を印刷する場合は 300 dpi 以上でエクスポートしてください。

## externalize を使用して画像をキャッシュする

大きなドキュメント内では、コンパイルのたびに TikZ 画像が再描画され、少数の複雑なプロットがビルド時間の大半を占める可能性があります。 「外部」ライブラリは、各画像を一度独自の PDF にコンパイルし、画像のコードが変更されるまでキャッシュされたファイルを再利用することでこの問題を修正します。

```latex
\usetikzlibrary{external}
\tikzexternalize[prefix=tikz-cache/]
```

`prefix` オプションは、生成されたファイルを独自のフォルダーに保存します。外部化では、サブコンパイルを生成するモードでコンパイラが実行されるため、シェル エスケープを有効にする必要があり、一部のセットアップとの相互作用が不十分になります。それが問題になる場合は、大きな画像をそれぞれ独自の「スタンドアロン」ファイルに移動し、コンパイルされた PDF を含めてください。これにより、より少ない機械を使用して、同じキャッシュを手動で行うことができます。一般的なコンパイル時間については、[PDF の待ち時間の短縮](/learn/speed-up-compilation/) で説明されています。

よくある間違いの 1 つは警告に値します。それは、レンダリングされた図をスクリーンショットして PNG を取得しないでください。スクリーンショットは画面解像度をキャプチャします。これは、スライド プレビューでは許容範囲内に見えますが、その他の場所では不鮮明に見えます。 PDF から変換します。解像度は自由に選択できます。
