# 演講、海報和會議本身

接受電子郵件，相機準備就緒，航班已預訂。現在是沒人教的部分：會議。以下是實際發生的情況，以及如何很好地使用它。

## 談話

如果您的論文有口頭時段，您將進行一次演講，通常為 10 到 20 分鐘，並提出問題。數學是殘酷而自由的：你無法展示論文。你可以提出一個想法、一個關鍵人物、一個閱讀這篇論文的理由。

- [ ] 觀眾應該記住的一句話
- [ ] 大約每分鐘一張幻燈片，越少越好
- [ ] 大字體、大數字、最小文本
- [ ] 大聲排練至少三次，一次只用於計時
- [ ] 準備兩個最可能的問題

用 LaTeX 建造甲板，以便您的符號與論文相匹配：[Beamer basics](/learn/beamer-basics/) 幫助您實現目標。

## 海報展示環節

大多數被接受的論文都以海報的形式出現，而海報會議通常是會議中最好的部分：與那些選擇停下來工作的人進行兩個小時的直接對話。設計一個在兩米外清晰可見的版本，並準備三個版本的宣傳：為路過的人提供的 30 秒版本，為感興趣的人提供的 2 分鐘版本，以及為在飛機上閱讀您論文的人提供的長版本。有關 LaTeX 方面，請參閱[會議海報](/learn/conference-poster/)。

## 閃電演講與錄音

兩種讓初次接觸者感到驚訝的格式：

- **閃電演講**：有些場館為每張海報提供 1 到 2 分鐘的預告時段。一張幻燈片，一張聲明，“到 42 號海報來找我。”
- **錄音**：許多會議需要預先錄製演講視頻，在活動前幾週上傳，並有自己的截止日期。仔細檢查演示者說明電子郵件；這個最後期限隱藏在第四段。

## 網路才是真正的重點

談話內容都有記錄。這些論文都在網路上。你以後無法下載的一件事是走廊：會議之間的對話、海報上的問題、與引用與你相同論文的人共進晚餐。其中一些對話變成了合作、博士後邀請和終身同事。

如果網路聽起來很可怕，請使用內建的作弊代碼：詢問人們的工作情況。研究人員喜歡談論他們的工作，「我看到了你的海報，你是如何處理 X 的？」是一個完整的社會策略。也可以參加稍微超出您所在區域的會談；這就是新想法的來源。

## 工件和程式碼發布

期望發生了變化：審查者和讀者越來越期望論文背後的程式碼、數據或工件能夠公開。許多場館都運行帶有徽章的工件評估軌道。實用版：

- [ ] 带有自述文件的公共存储库，说明如何重现主要结果
- [ ] 引脚依赖版本
- [ ] 連結論文與海報中的儲存庫
- [ ] 明确许可代码

如果您的專案已經存在於具有 GitHub 同步功能的 Git 中（請參閱[與 GitHub 同步](/learn/sync-with-github/)），則發布主要是清理過程，而不是遷移。

## 會後

將最終版本發佈到人們可以找到的地方，更新您的網站，並分享一句話要點。然後休息。下一課，[你的第一篇論文，端到端](/learn/first-paper-roadmap/)，將整個管道放在一張地圖上。
