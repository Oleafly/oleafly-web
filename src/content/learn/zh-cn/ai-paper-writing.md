# 保持诚实的草稿帮助

语言模型是现在撰写的许多论文的一部分。有用的问题是在哪里划清界限。模型可以帮助您更清楚地表达您所知道的内容。不能相信它会为你了解事情。帮助措辞可以节省时间，风险很小。让模型发明事实或来源会将捏造的材料以您的名义记录在学术记录中。

## 模型真正有帮助的地方

结构工作是最好的利用。给定您的摘要和章节列表，模型可以建议不同的顺序，注意您的贡献隐藏在第 5 节中，或者猜测持怀疑态度的审稿人会问什么。你可以根据你对工作已有的了解来判断每一个建议。压缩的工作原理是一样的：交出你自己在十篇相关论文上的粗略笔记，并要求一个更紧凑的段落。事实归你所有；模型执行句子木工。对你所写的散文进行清晰的编辑是常见的情况。缩短、理清和删除你自己的段落中的行话是工作模型做得很好的方法，而且你仍然可以决定其含义是否得以保留。

## 模型出现危险故障的地方

永远不要让模型提供引用。当要求提供参考资料时，模型会生成看起来合理的条目，其中包含真实的地点、听起来真实的作者以及发明的标题或 DOI。它们生成引文的样子，而不是检索存在的内容。每一份参考文献都必须是您自己找到并与实际论文进行核对的。 [构建持久的 .bib](/learn/create-bibliography/) 涵盖保持数据库健全。同样警惕技术内容。要求“填写推导”的模型将产生可能有细微错误的自信步骤，而您无法发现的错误就无法发布。也不要提交你没有仔细阅读过的散文。示范文本可能会夹杂一些夸张的说法和小的事实错误，一旦提交，每句话都是你的。

## 确保安全的护栏

将手稿保存在 Git 下，这样每个模型辅助的更改都是可见的差异，您可以查看和恢复。 [将论文放在 GitHub 上](/learn/sync-with-github/) 显示了设置。 Oleafly 的助手添加了自己的批准差异和预编辑检查点，如[Oleafly 内部的助手](/learn/oleafly-ai/) 中所述。还要检查您场地的政策。许多期刊和会议现在都要求披露人工智能的协助，并且几乎所有期刊和会议都要求作者对内容承担全部责任，无论使用何种工具。经验法则：仅在可以比您自己编写的速度更快地验证输出的情况下使用该模型。其他的，自己写吧。
