# Oleafly 内のアシスタント

Oleafly には、別のチャット ウィンドウではなくプロジェクト内で動作する AI アシスタントが含まれています。一般的なチャットボットに LaTeX を貼り付けるのとは異なり、LaTeX は独自の API キーで実行され、編集中のプロジェクトを読み取ることができ、ファイルに触れる前に承認のために提案されたすべての変更を表示します。

## あなたのキー、あなたのプロバイダー

アシスタントは、Oleafly のサーバーを介してモデル呼び出しを行いません。サポートされている 9 つのホスト型プロバイダーのいずれかの API キーを指定するか、アプリをローカルの Ollama インストールに指定し、独自のハードウェアで実行されているモデルを使用します。リクエストは、プロバイダーの条件に基づいて、マシンから設定したプロバイダーに送信され、プロバイダーに料金を直接支払います。どのモデルを選択するか、キーまたは Ollama をセットアップする方法については、[AI セットアップ](/docs/ai-setup/) で説明されています。

## アシスタントに表示されるもの

質問したり編集をリクエストすると、アシスタントはプロジェクトのマップから作業し、編集中の章、マクロを定義するプリアンブル、引用質問の背後にある `.bib` ファイルなど、リクエストに関連するファイルを読み取ります。そのコンテキストが、実際の図 3 に関する「なぜ図 3 が次のページにフローティングしているのか」、またその編集内容が文書ですでに使用されている表記法やコマンドと一致する傾向がある理由に答えることができる理由です。

## たまたま発生した編集ではなく、自分でレビューした編集

アシスタントがファイルに直接書き込むことはありません。削除された行は赤、追加された行は緑で示され、変更が差分として提案され、それぞれを受け入れるか拒否します。受け入れられた変更が適用される前に、Oleafly は Git チェックポイントを記録するため、編集前の状態が常に [Git 履歴](/docs/git-history/) に記録されます。ファイルの削除は別個に処理され、アシスタントが他の操作を行っている場合でも、常に明示的な確認が必要です。

## コンパイラでループを閉じる

アシスタントはビルドの隣に存在するため、自身の作業をチェックできます。編集後、コンパイルをトリガーし、ログを読み取り、変更がエラーを修正することを目的としたものである場合は、そのエラーが解消されたかどうかを確認します。また、コンパイルされた PDF のテキストを読み取ることもできるため、要求された変更が実際に出力に表示されることを確認できます。モデルは依然として間違った LaTeX を生成するため、受け入れる内容を読んでください。利点は、壊れた提案は後からではなくループ内で捕らえられ、修正される傾向があることです。

日常的な仕組みは [チャット](/docs/ai-chat/) と [インライン編集](/docs/ai-inline-edit/) のドキュメントに記載されており、[Oleafly での 1 週間の執筆](/learn/oleafly-workflow/) では、アシスタントが完全な執筆ループのどこに当てはまるかを示しています。
