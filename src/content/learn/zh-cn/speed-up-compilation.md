# 缩短 PDF 等待时间

一篇需要九十秒完成的论文会改变你的写作方式。在进行小幅编辑后，您会停止重新编译，错误会堆积起来，看不见，而使 LaTeX 令人愉快的反馈循环也消失了。在优化之前，先了解时间都花在哪里了。在大多数长文档中，主导构建的不是包的数量，而是少量的重资产，尤其是大图像和复杂的 TikZ 图片。下面的技术直接攻击这些。

## 起草时跳过数字

“draft”选项使 LaTeX 用相同大小的空框替换每个图像，这在跳过图像处理的同时保留了布局和分页符：

```latex
\documentclass[draft]{article}
```

类级别的“草稿”还用黑条标记过满的线条，有些人觉得很有用，而另一些人则觉得很吵。要将效果限制在图像上，请将选项传递给包，如 `\usepackage[draft]{graphicx}`，或使用 `\includegraphics[draft]{...}` 传递给单个罪魁祸首。请记住在共享 PDF 之前将其删除，因为对于不知道该选项的人来说，草稿版本看起来很糟糕。与草稿模式无关，按[放入图形](/learn/insert-images/)中所述，缩小一次巨大的照片，因为 40 MB 的图像会在每次编译时永远花费您的费用。

## 只编译当前章节

如果您的章节位于使用“\include”拉入的单独文件中，则“\includeonly”命令将构建限制为您命名的文件：

```latex
\includeonly{chapters/04-results}
```

将其放在序言中，LaTeX 会在阅读其他文件的“.aux”文件的同时编译该章，因此文档其余部分的页码和交叉引用大致保持正确。这是论文最大的节省，通常可以将一分钟的构建时间缩短为几秒钟。它仅适用于“\include”，不适用于“\input”，这是按照[将文档拆分为文件](/learn/split-chapter-files/)中所述构造长文档的原因之一。

## 缓存昂贵的图片

TikZ 图片在每次编译时都会从头开始重新绘制。 “external”库加载了“\usetikzlibrary{external}”和“\tikzexternalize”，将每张图片编译为其自己的 PDF 一次，并重复使用它，直到代码更改。该设置具有锐利的边缘，并且将大图片移动到独立文件中的手动替代方案也同样有效；两者都包含在[独立 TikZ 到 PDF 或 PNG](/learn/tikz-export/) 中。

## 更少的传球次数，更快的铁杆

参考书目和交叉引用解析需要多次传递，但在起草散文时，您很少需要它们，因此一次快速传递就足够了，完整的序列可以等到您检查参考文献为止。硬件和位置也很重要：本地引擎在您自己的 CPU 上编译，无需上传或队列，这就是 Oleafly 运行构建的方式。

将“\includeonly”和草图一起应用，即使是一篇大型论文通常也会在几秒钟内返回，这是您在每个段落之后再次开始重新编译的时间点。
