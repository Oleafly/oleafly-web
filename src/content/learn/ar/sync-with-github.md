# ضع الورقة على جيثب

مخطوطة LaTeX عبارة عن نص عادي، مما يجعلها مناسبة تمامًا لـ Git. تصبح كل مسودة التزامًا يمكنك الرجوع إليه، ويكون كل تغيير مرئيًا على شكل فرق على مستوى السطر، ويمنحك GitHub نسخة خارج الموقع بالإضافة إلى طريقة للمؤلفين المشاركين لسحب الحالة الحالية. لا شيء من هذا يتطلب Git المتقدم. ربما تحتاج الورقة إلى خمسة أوامر، تُستخدم باستمرار.

## الإعداد الأولي

```bash
git init
# add a .gitignore for *.aux *.log *.out *.toc *.synctex.gz
git add main.tex refs.bib figures/
git commit -m "Initial manuscript"
gh repo create my-paper --private --source=. --push
```

قم بتشغيل هذا مرة واحدة في مجلد المشروع. الخطوة ".gitignore" مهمة أكثر مما تبدو. تقوم كل ترجمة بإعادة إنشاء ملفات `.aux`، و`.log`، و`.out`، و`.toc`، و`.synctex.gz`، وتنفيذها يدفن تغييراتك الحقيقية تحت ضجيج الآلة ويخلق تعارضات دمج لا طائل من ورائها بين المؤلفين المشاركين. تتبع فقط ما قمت بتأليفه: مصادر ".tex"، وقاعدة بيانات ".bib"، والأشكال، وأي ملفات فئة أو نمط قدمها لك المكان. يعد ملف PDF منتج بناء أيضًا. تتركه معظم الفرق وتعيد البناء محليًا، على الرغم من أن إرفاق أحد الإصدارات بإصدار موسوم يعد طريقة معقولة لتجميد الإصدار المقدم. حافظ على خصوصية المستودع حتى يصبح العمل عامًا. المخطوطة غير المنشورة ليست شيئًا يمكن فهرسته.

## العادات التي تبقي المؤلفين المشاركين عاقلين

قم بإجراء كل تغيير منطقي واحد، مثل "مراجعة مقدمة القسم 3" أو "إضافة جدول الاجتثاث". يُقرأ التاريخ بعد ذلك كقصة للصحيفة، ويمكن التراجع عن التعديل السيئ دون أضرار جانبية. اسحب قبل أن تبدأ جلسة الكتابة وادفع عندما تتوقف. تنمو تعارضات الدمج مع الوقت الذي تقضيه الفروع بعيدًا. لا تقم مطلقًا بدفع فرع مشترك بالقوة بمجرد أن يسحبه المؤلفون المشاركون: فهذا يعيد كتابة التاريخ تحت أقدامهم. احتفظ بالقطع الأثرية الثنائية الكبيرة (مجموعات البيانات ومقاطع الفيديو) خارج مستودع الورق. قم بالارتباط بأرشيف أو استخدم مستودع بيانات منفصل. يقوم Git بتخزين كل نسخة من كل ثنائي إلى الأبد.

إحدى العادات الخاصة بـ LaTeX: كتابة جملة واحدة في كل سطر مصدر تجعل الفروق أكثر قابلية للقراءة بشكل كبير، لأن التعديل المكون من كلمة واحدة يظهر كتغيير في سطر واحد بدلاً من فقرة مُعاد تدفقها.

## كيف تناسب أوليفلي

كل مشروع Oleafly هو مجلد عادي على القرص، لذلك تعمل هذه الأوامر عليه دون تغيير. يمكن للتطبيق أيضًا إنشاء التزام Git تلقائيًا بعد كل عملية ترجمة ناجحة، مما يمنحك شبكة أمان دقيقة بين التزاماتك المتعمدة. راجع [سجل Git](/docs/git-history/). للتعرف على أنماط التعاون المبنية على هذا، بما في ذلك تبادل التصحيح وملكية الفصل، راجع [Coauthor بدون مؤشر مباشر](/learn/offline-collaboration/).
