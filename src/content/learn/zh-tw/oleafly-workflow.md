# Oleafly 寫作一周

這就是 Oleafly 中論文的日常實際情況，從空專案到可以發送給合著者的草稿。該應用程式不需要帳戶，也不需要伺服器：專案是磁碟上「.tex」、「.bib」和圖形檔案的資料夾，下面的所有內容都在該資料夾上運行。

## 第一天：從範本開始

在庫中建立一個項目，可以是空白項目，也可以使用常見格式（例如 IEEE 和 ACM 論文或論文框架）的[範本](/templates/)。模板會立即為您提供一個編譯文檔，其中類選項和序言已經合理，這比第一天逐行組裝序言要好。在編寫任何內容之前，請按一下「編譯」以確認您獲得了 PDF。

## 週中：寫入-編譯循環

一週的大部分時間都是在編輯器和 PDF 窗格之間循環。編輯器會自動完成專案中存在的命令、環境以及標籤和引用鍵，並且斜線命令會插入更大的結構，例如圖形和表格，而無需您記住其樣板。經常編譯，因為兩分鐘前編寫的文本中很容易出現新的錯誤，而一下午的更改後出現的錯誤則不然。 SyncTeX 將兩個窗格連接在一起：按一下 PDF 中的一個段落可跳到其原始程式碼行，或從原始程式碼跳到 PDF，這在修改長文件的特定頁面時最為重要。

## 隨時引用

在專案中保留一個「.bib」文件，並在編寫時使用「\cite{...}」進行引用，讓自動完成功能提供鍵。在寫作時添加參考文獻的成本很低。重建三週的「需要引用」佔位符則不然。如果條目來自 Zotero 或出版商的匯出，[BibTeX 驗證器](/tools/bibtex-validator/) 會在遺失的欄位作為看起來奇怪的引用出現之前捕獲它們。完整的流程在[從 .bib 鍵到文字參考](/learn/add-itations/) 中描述。

## 沒有儀式的歷史

Oleafly 可以在每次成功編譯後自動記錄 Git 提交，因此一週會留下您可以檢查或回滾的工作狀態時間表。當草稿值得分享時，將資料夾推送到私人 GitHub 儲存庫；[將論文放在 GitHub 上](/learn/sync-with-github/) 顯示了設定。

## 可選：助手

如果您為託管提供者新增 API 金鑰，或將應用程式指向本機 Ollama，助手可以回答有關您的專案的問題，提出批准差異背後的編輯建議，並進行編譯以檢查自己的工作。可選：上面的每一步都可以在沒有它的情況下工作。詳細資訊請參閱[Oleafly 內的助手](/learn/oleafly-ai/)，應用程式背後更廣泛的設計意圖位於[入門](/docs/getting-started/) 和[哲學](/docs/philosophy/)。
