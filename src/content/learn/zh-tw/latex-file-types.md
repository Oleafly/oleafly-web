# 真實專案中的文件

編譯後打開任何真實的 LaTeX 專案的資料夾，您會發現檔案比您編寫的要多得多。這讓大多數初學者感到驚訝，並擔心刪除錯誤的內容會使資料夾永遠混亂。澄清這一點的區別是：有些文件是您編輯的源文件，有些是模板或包提供的樣式，其餘的是編譯器在每次運行時重新創建的臨時空間。

## 你寫的文件

您的“.tex”文件保存實際文件：文字、部分、圖形和數學。 「.bib」檔案是您的參考書目資料庫，您可能引用的每篇論文或書籍都有一個條目；您可以手動維護它或從 Zotero 等參考管理員匯出它。這些是值得備份並放入版本控制的文件，因為其他所有內容都可以從它們重建。

## 範本為您提供的文件

`.cls` 檔案定義一個文檔類，即您在 `\documentclass{...}` 中命名的內容。期刊和會議都有自己的期刊和會議，因此每份提交的內容看起來都是一樣的，而且您幾乎從不編輯。 `.sty` 檔案是一個套件：使用 `\usepackage` 載入的可重複使用巨集和設定。當您想要在多個文件之間共用自訂命令時，您只需自己編寫一個。 「.bst」文件描述了 BibTeX 引文風格，同樣通常只是由某個地點放入。

## 編譯器產生的文件

`.aux` 檔案儲存編譯過程之間的交叉引用和引用資料；永遠不要編輯它，並且可以隨意刪除它，因為下一次編譯會重寫它。 「.log」檔案記錄了編譯器所做的一切，只有在出現問題時才值得開啟。 `.pdf` 是您真正想要的輸出。

|擴充|角色 |手作編輯？ |
| --- | --- | --- |
| `.tex` |原始檔和章節|是的 |
| `.bib` |參考書目資料庫|是（或從 Zotero 匯出）|
| `.cls` |文檔類別|很少有供應商範本 |
| `.sty` |包/樣式檔|當寫自己的巨集|
| `.bst` | BibTeX 風格 |很少|
| `.aux` |交叉引用資料| **否：**產生 |
| `.log` |編譯日誌 |調試時閱讀 |
| `.pdf` |輸出|查看/提交 |

## 可擴展的專案佈局

```text
paper/
 main.tex
 chapters/
 figures/
 refs.bib
```

頂層的一個「main.tex」充當入口點，章節位於它們自己的資料夾中，並透過「\input」或「\include」拉入，圖像位於「figures/」中，參考書目位於一個「refs.bib」中。無論專案是四頁論文還是論文，這種佈局都保持易於管理。 [分割章節檔案](/learn/split-chapter-files/) 顯示各個部分如何連結。

如果您使用 Git，請將“*.aux”、“*.log”和其他產生的檔案新增至“.gitignore”，以便您的歷史記錄僅追蹤真實來源。 Oleafly 專案是磁碟上的普通資料夾，因此此建議不變地適用於那裡。最常見的錯誤是相反的錯誤：在尋找奇怪的編譯錯誤時，刪除“.aux”檔案通常是修復方法，因為運行中斷後的陳舊檔案可能會毒害其後的每個編譯。
