# Oleafly 내부의 조수

Oleafly에는 별도의 채팅 창이 아닌 프로젝트 내부에서 작동하는 AI 도우미가 포함되어 있습니다. LaTeX를 일반 챗봇에 붙여넣는 것과 달리 자체 API 키로 실행되고, 편집 중인 프로젝트를 읽을 수 있으며, 파일을 터치하기 전에 승인을 위해 제안된 모든 변경 사항을 표시합니다.

## 귀하의 키, 귀하의 공급자

어시스턴트는 Oleafly의 서버를 통해 모델 호출을 수행하지 않습니다. 지원되는 9개의 호스팅 공급자 중 하나에 대한 API 키를 제공하거나 앱이 로컬 Ollama 설치를 가리키도록 하고 자체 하드웨어에서 실행되는 모델을 사용합니다. 요청은 해당 공급자의 조건에 따라 귀하의 시스템에서 귀하가 구성한 공급자로 이동하며 귀하는 공급자의 요율에 따라 공급자에게 직접 비용을 지불합니다. 어떤 모델을 선택할지, 키나 Ollama를 설정하는 방법은 [AI 설정](/docs/ai-setup/)에서 다룹니다.

## 어시스턴트가 볼 수 있는 것

질문을 하거나 편집을 요청하면 어시스턴트는 프로젝트 맵에서 작업하고 편집 중인 장, 매크로를 정의하는 서문 또는 인용 질문 뒤에 있는 '.bib' 파일과 같은 요청과 관련된 파일을 읽습니다. 이러한 맥락에서 실제 그림 3에 대해 "그림 ​​3이 다음 페이지로 이동하는 이유"에 대해 답할 수 있고 해당 편집 내용이 문서에서 이미 사용하는 표기법 및 명령과 일치하는 경향이 있는 이유입니다.

## 방금 발생한 수정사항이 아닌 사용자가 검토한 수정사항

도우미는 파일에 직접 쓰지 않습니다. 제거된 선은 빨간색이고 추가된 선은 녹색인 차이점으로 변경 사항을 제안하며 각 항목을 수락하거나 거부합니다. 승인된 변경 사항이 적용되기 전에 Oleafly는 Git 체크포인트를 기록하므로 편집 전 상태는 항상 [Git 기록](/docs/git-history/)에서 한 단계 떨어져 있습니다. 파일 삭제는 별도로 처리되며 보조자가 수행하는 작업이 무엇이든 항상 명시적인 확인이 필요합니다.

## 컴파일러로 루프 닫기

어시스턴트는 빌드 옆에 있기 때문에 자체 작업을 확인할 수 있습니다. 편집 후에는 컴파일을 트리거하고 로그를 읽을 수 있으며, 변경 사항이 오류를 수정하기 위한 것이라면 해당 오류가 사라졌는지 확인하세요. 또한 컴파일된 PDF의 텍스트를 읽을 수 있으므로 요청된 변경 사항이 실제로 출력에 표시되는지 확인할 수 있습니다. 모델은 여전히 ​​잘못된 LaTeX를 생성하므로 수용하는 내용을 읽어보십시오. 장점은 잘못된 제안이 나중에 사용자가 아닌 루프 내부에서 포착되어 수정되는 경향이 있다는 것입니다.

일상적인 메커니즘은 [채팅](/docs/ai-chat/) 및 [인라인 편집](/docs/ai-inline-edit/) 문서에 있으며, [Oleafly에서 글쓰기 일주일](/learn/oleafly-workflow/)은 어시스턴트가 전체 쓰기 루프에 적합한 위치를 보여줍니다.
