## クラスファイルを受け入れ、残りをフェンスします

大学の `.cls` (および必要な `.bst` / ロゴ ファイル) をプロジェクトに配置します。
クラスを書き換えないでください。マクロ、パッケージ、章のコンテンツを配置します。
あなたが管理するファイル:

```text
thesis/
  main.tex
  macros.tex
  chapters/
  figures/
  university.cls
```

最新のエンジンでクラスが壊れた場合は、次の方法で優先順位を付けます。
[コンパイルできない大学のクラス ファイル](/learn/fix-broken-template/)。
論文事務局がどのエンジンを受け入れているかを文書化します (pdfLaTeX vs XeLaTeX vs
`fontspec` に投資する前に、LuaLaTeX) を確認してください。

## ファイルとしての章

1 つのルートには次のものが含まれます。

```latex
\include{chapters/intro}
\include{chapters/background}
\include{chapters/methods}
\include{chapters/results}
\include{chapters/conclusion}
```

共著者が論文の基礎となる論文を手伝っている場合でも、自分で章を所有します。
順序を変更してもパスが安定するように、Figure を「figures/chapter3/」の下に保持します。
草案作成中に「\includeonly{chapters/methods}」を使用すると、全論文がコンパイルされます。
すべての方程式編集のコストではありません。
[章ファイルを分割](/learn/split-chapter-files/)。

ラベルはプロジェクト全体で一意である必要があります (プロジェクト内の `eq:main` ではなく `eq:ch3-main`)
すべてのファイル)。プロジェクト全体の構造ビューとライブ参照チェックのヘルプ
200ページのツリー。

希望（数値、著者年、脚注を多用する人文科学スタイル）。混ぜないでください

＃＃ スピード

## バックアップは履歴と同じではありません

Dropbox のコピーはバックアップです。 Git は、議論がどのように変化したかの物語です。
章がコンパイルされるときにコミットします。プライベート GitHub または GitLab リモートにプッシュします。

[Oleafly](https://github.com/Oleafly/Oleafly/releases/latest) は、
プロジェクトごとの実際のリポジトリ、コンパイルとアイドル編集の成功後のチェックポイント、
プロジェクト全体の構造ビューと SyncTeX の隣に、ワンクリックで復元します。
これはチャプターファイル全体で引き続き機能します。そうすることで習慣を抜け出すのが難しくなります。
どのエディターでも注意深い Git を使用しても、同じ規律を得ることができます。論文
18 か月目に「git init」を忘れずに行うことに依存すべきではありません。

## ソフトバインドとハードバインドのチェックリスト

印刷または入金する前に:

- クラスファイルとエンジンは論文事務局のルールに一致します。
- 前付のページ番号が正しい。必要に応じて署名ページが表示されます。
- すべての `\ref`/`\cite` が解決されます。 「[?]」はありません。
- 必要に応じて図や表を記載します。キャプションに一貫性がある。
- 余白とフォント サイズはチェックリスト PDF (テスト ページを印刷) に合格します。
- ソース + PDF + コミットハッシュはデポジット後にアーカイブされます。

## 図、表、および「リスト」ページ

多くの論文発表オフィスでは、図と表のリストが必要です。キャプションは次のようにする必要があります
一貫性があり、メソッドセクション全体を 20 行のキャプションにダンプしないでください。使用する
リストには短いタイトル、本文には長い説明キャプションが含まれます。
クラスはオプションの短いキャプションをサポートします。

バージョン管理の章、変更点に関する注記 (表記、拡張)
実験、統一導入）。
