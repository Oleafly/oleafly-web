# 真实项目中的文件

编译后打开任何真实的 LaTeX 项目的文件夹，您会发现文件比您编写的要多得多。这让大多数初学者感到惊讶，并且担心删除错误的内容使文件夹永远混乱。澄清这一点的区别是：有些文件是您编辑的源文件，有些是模板或包提供的样式，其余的是编译器在每次运行时重新创建的临时空间。

## 你写的文件

您的“.tex”文件保存实际文档：文本、部分、图形和数学。 “.bib”文件是您的参考书目数据库，您可能引用的每篇论文或书籍都有一个条目；您可以手动维护它或从 Zotero 等参考管理器导出它。这些是值得备份并放入版本控制的文件，因为其他所有内容都可以从它们重建。

## 模板为您提供的文件

`.cls` 文件定义一个文档类，即您在 `\documentclass{...}` 中命名的内容。期刊和会议都有自己的期刊和会议，因此每份提交的内容看起来都是一样的，而且您几乎从不编辑。 `.sty` 文件是一个包：使用 `\usepackage` 加载的可重用宏和设置。当您想要在多个文档之间共享自定义命令时，您只需自己编写一个。 “.bst”文件描述了 BibTeX 引文风格，同样通常只是由某个地点放入。

## 编译器生成的文件

`.aux` 文件存储编译过程之间的交叉引用和引用数据；永远不要编辑它，并且可以随意删除它，因为下一次编译会重写它。 “.log”文件记录了编译器所做的一切，只有在出现问题时才值得打开。 `.pdf` 是您真正想要的输出。

|扩展|角色 |手工编辑？ |
| --- | --- | --- |
| `.tex` |源文件和章节|是的 |
| `.bib` |参考书目数据库|是（或从 Zotero 导出）|
| `.cls` |文档类|很少有供应商模板 |
| `.sty` |包/样式文件|当编写自己的宏时|
| `.bst` | BibTeX 风格 |很少|
| `.aux` |交叉引用数据| **否：**生成 |
| `.log` |编译日志 |调试时阅读 |
| `.pdf` |输出|查看/提交 |

## 可扩展的项目布局

```text
paper/
 main.tex
 chapters/
 figures/
 refs.bib
```

顶层的一个“main.tex”充当入口点，章节位于它们自己的文件夹中，并通过“\input”或“\include”拉入，图像位于“figures/”中，参考书目位于一个“refs.bib”中。无论项目是四页论文还是论文，这种布局都保持易于管理。 [拆分章节文件](/learn/split-chapter-files/) 显示各个部分如何连接。

如果您使用 Git，请将“*.aux”、“*.log”和其他生成的文件添加到“.gitignore”，以便您的历史记录仅跟踪真实来源。 Oleafly 项目是磁盘上的普通文件夹，因此此建议不变地适用于那里。最常见的错误是相反的错误：在寻找奇怪的编译错误时，删除“.aux”文件通常是修复方法，因为运行中断后的陈旧文件可能会毒害其后的每个编译。
