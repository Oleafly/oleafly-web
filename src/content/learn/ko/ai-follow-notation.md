# 모델에 기호 테이블 제공

모델에게 수학 텍스트의 초안을 작성하거나 수정하도록 요청하면 표기법이 표류하는 동안 산문은 대개 잘 돌아옵니다. 벡터 `\vect{x}`는 한 단락에서는 `\mathbf{x}`로 반환되고 다른 단락에서는 `\vec{x}`로 반환됩니다. `\E[X]`라고 쓴 기대값은 `\mathbb{E}(X)`로 돌아옵니다. 각 변형이 컴파일되므로 오류가 없습니다. 불일치는 독자가 세 가지 다른 방식으로 작성된 동일한 객체를 발견할 때만 나타납니다. 이 모델은 존재하는 모든 표기 규칙을 확인했으며 지침 없이도 모든 표기 규칙의 샘플을 확인했습니다. 명시적으로 당신의 것을 건네주세요.

## 매크로를 사용하면 표기법을 적용할 수 있습니다.

기초 작업은 AI와 독립적이며 어쨌든 수행할 가치가 있습니다. 모든 반복 기호를 매크로를 통해 라우팅하므로 소스는 원시 `\boldsymbol{x}` 대신 `\vect{x}`라고 말합니다. 이를 통해 각 개념에 하나의 이름이 부여되고, 하나의 정의를 편집하여 전체 논문의 스타일을 변경할 수 있으며, 변형을 만들어내는 대신 고수할 수 있는 작은 어휘가 모델에 제공됩니다. 매크로 정의는 [사용자 정의 명령](/learn/custom-commands/)에서 다룹니다.

## 프롬프트에 붙여넣을 내용

실제 요청과 함께 간단한 표기 블록을 포함하세요. 즉, 매크로 정의와 각각의 용도를 설명하는 주석이 한 줄에 하나씩 포함됩니다.

```latex
% vectors: bold italic \vect{x}
% matrices: bold upright \mat{A}
% expectation: \E{X}
```

그런 다음 제약 조건을 직접 명시합니다. "이러한 개념에는 이러한 매크로만 사용하세요. 나열된 항목에 대해 새로운 표기법을 도입하지 마세요. 목록에 없는 기호가 필요한 경우 기호를 만드는 대신 그렇게 말하세요." 모델은 모호한 "내 스타일에 맞춰라"라고 말하는 것보다 구체적이고 확인 가능한 지침을 훨씬 더 잘 따릅니다. 전체 논문의 경우 블록을 서문 근처에 짧은 표기 주석으로 유지하여 최신 상태를 유지하고 붙여넣을 준비를 하세요.

## 기계적으로 확인

매크로 레이어를 사용하면 검사 비용이 저렴해집니다. 모든 벡터가 `\vect{...}`여야 하는 경우 모델 출력의 원시 `\mathbf{` 또는 `\vec{`는 수학을 다시 읽는 대신 텍스트 검색을 통해 찾을 수 있는 위반입니다. 붙여넣은 모든 항목에 대해 해당 검색을 실행하고 낙오자를 수정하면 모델 지원 편집 내용이 얼마나 많이 논문에 포함되더라도 표기법은 균일하게 유지됩니다.

## 올리플리 내부

[Oleafly의 보조자](/learn/oleafly-ai/)는 매크로가 있는 서문을 포함하여 프로젝트 파일을 읽으므로 일반적으로 알려주지 않고 정의된 명령을 선택합니다. 명시적인 지시는 여전히 도움이 됩니다. 매크로가 존재한다는 것을 보는 것은 그것이 필수라는 말을 듣는 것보다 약합니다. 요청에 한 줄을 추가하고("서문의 표기법 매크로 사용") 변경 사항이 적용되기 전에 빨간색/녹색 차이점을 검토하세요. 이는 소스에서 드리프트를 유지합니다.
