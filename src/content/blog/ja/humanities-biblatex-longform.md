## 柔軟性のためにビブラテックスを好む

「biblatex」は、脚注、冗長スタイル、および速記を従来のものよりも適切に処理します
ほとんどの人文科学ワークフロー向けの BibTeX:

```latex
\usepackage[backend=biber,style=verbose-ibid]{biblatex}
\addbibresource{sources.bib}
```

一般的な代替案には、`authortitle`、`verbose`、ジャーナル固有のスタイル、
またはあなたの部門が義務付けているものなら何でも。まずハンドブックと照合してから、
最も近いビブラテックススタイル。背景:
[BibTeX または biblatex](/learn/bibtex-vs-biblatex/)。

pdflatex だけでなく、**biber** (またはスタイルに必要なバックエンド) を実行します。空の
参考文献目録はほとんどの場合、バックエンドまたはパスの間違いです。エントリを検証する
提出前: [BibTeX バリデーター](/tools/bibtex-validator/)。

## アーカイブと Web ソース

手紙、原稿、Web サイトには、「@article」エントリを記録するフィールドが必要です
気にしないでください:

- `urldate` を含む Web ソースの場合は `@unpublished` または biblatex `@online`
- アーカイブの場所、コレクション、原稿のフォリオ
- 2年後も理解できる安定したキー

不完全なエントリは、参考文献がまばらになるまで静かに失敗します。 1 つを優先します
`.bib` (またはプロジェクトによる小さなセット) をコピーアンドペーストした脚注テキストがずれている
引用された作品と同期していません。

## 脚注と文末脚注

多くの人文科学スタイルでは脚注が必要です。 「biblatex」の冗長スタイルと
`\footcite` / 自動脚注引用は多くの領域をカバーします。もし
部門は文末脚注を必要としているので、早めに設定してください。の 3 つの章を変換する
脚注の引用投稿の週は悲惨です。

実質的な余談は短くしてください。脚注が段落全体である場合は、次のことを尋ねます。
それは本文に含まれます。読者は流し読みをします。

## 章と重要なエディション

本の長さのプロジェクトには、「本」、「回想録」、または大学の論文のクラスが必要です。
章ごとの「\include」:

```latex
\include{chapters/ch1-intro}
\include{chapters/ch2-archive}
```

他の章への相互参照には、ハードコーディングではなく、`\ref` / `\cref` を使用する必要があります。
「第 4 章を参照」順序を変更すると腐ってしまう文字列。リストを含む構造ビュー
ファイル全体の見出しは、200 ページの草稿に役立ちます。コンパイルも同様です
1 つの章を改訂するときに「\includeonly」を実行します。

クリティカルエディションと対訳テキストには専用のパッケージがあります。発明しないでください
クラスが維持されているかどうかを確認するまで、生のミニページを含むレイアウト
あなたの言語にはすでに存在します。

## 引用と言語

論文の言語に応じて適切な引用符を使用してください (`csquotes` は、
ネストされた引用符と言語対応マーク)。数行を超える引用符をブロックする
手動でインデントを挿入するのではなく、引用環境を使用する必要があります。
2 列レイアウトまたは余白が変更された場合。

多言語プロジェクトの場合、「fontspec」と言語を使用した XeLaTeX または LuaLaTeX
このパッケージは、1990 年代の「inputenc」ハックを積み重ねるよりも苦痛が少ないです。フォントを選択してください
できないフォントで第 3 章を書く前に、必要なスクリプトをカバーしてください。
それらをレンダリングします。

## 画像、地図、フェアユースに関するメモ

地図や原稿の写真は通常、TikZ ではなく外部の PDF/PNG に含まれます。
出典と許可ステータスを示すキャプション。高解像度マスターを屋外に保管する
巨大な場合は git 履歴。圧縮された図を紙にコミットする
実際に使用し、マスターがどこに住んでいるのかを README にメモしてください。

## 数年分の紙幣のローカル所有権

論文は複数年にわたるファイル ツリーです。ブラウザプロジェクト内にのみ保持する
1 つのアカウントに関連付けられていると、学生が教育機関を変更したり、アクセスできなくなったりする場合にリスクが生じます。
卒業後。

プレーン フォルダーと Git をローカルでコンパイルすると、より古くなります。
[Oleafly](https://github.com/Oleafly/Oleafly/releases/latest) はそれを目的としています
一種の長い文書。章全体、プロジェクト全体の構造ビューを取得します
参照と引用、散文のオフラインの綴りと文法 (引用キーをスキップします)、および
アカウントなしの実際の Git チェックポイント。同じファイルを引き続き開くことができます
他のエディタでも。所有権がポイントです。

最後には驚かせてください。

## 事前提出

- Biber/bibtex はクリーンに動作します。 `[?]` は引用しません。
- 脚注のスタイルは部門に一致します。
- 並べ替え後に章の相互参照が更新されました。

- アップロードポータルのレシートだけでなく、ソースと PDF の両方がアーカイブされます。
