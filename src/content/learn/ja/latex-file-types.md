# 実際のプロジェクト内のファイル

コンパイル後に実際の LaTeX プロジェクトのフォルダーを開くと、作成したファイルよりもはるかに多くのファイルが見つかるでしょう。ほとんどの初心者はこれに驚きますが、間違ったものを削除してしまうのではないかという恐怖から、フォルダーがいつまでも散らかったままになってしまいます。この違いを明確にするのは、一部のファイルは編集するソースであり、一部はテンプレートまたはパッケージによって提供されるスタイルであり、残りはコンパイラが実行のたびに再作成する生成されたスクラッチ領域です。

## あなたが書き込むファイル

`.tex` ファイルには、テキスト、セクション、図、数式などの実際の文書が含まれます。 `.bib` ファイルは参考文献データベースであり、引用する論文または書籍ごとに 1 つのエントリが含まれます。手動で管理することも、Zotero などのリファレンス マネージャーからエクスポートすることもできます。これらのファイルは、他のすべてのファイルから再構築できるため、バックアップしてバージョン管理に置く価値があります。

## テンプレートが提供するファイル

`.cls` ファイルは、`\documentclass{...}` で指定するドキュメント クラスを定義します。ジャーナルやカンファレンスは独自のものを出荷するため、すべての投稿は同一に見え、編集することはほとんどありません。 `.sty` ファイルはパッケージです。再利用可能なマクロと設定は `\usepackage` でロードされます。カスタム コマンドを複数のドキュメントで共有する場合は、自分でコマンドを作成するだけです。 `.bst` ファイルは BibTeX 引用スタイルを記述しており、同様に通常は会場によってドロップされるだけです。

## コンパイラが作成するファイル

`.aux` ファイルには、コンパイル パス間の相互参照と引用データが保存されます。次回のコンパイルで書き換えられるため、決して編集しないでください。削除しても構いません。 `.log` ファイルにはコンパイラが行ったすべてのことが記録されており、何か問題が発生した場合にのみ開く価値があります。 `.pdf` は実際に必要な出力です。

|拡張子 |役割 |手動で編集しますか？ |
| --- | --- | --- |
| `.tex` |ソース文書と章 |はい |
| `.よだれかけ` |書誌データベース |はい (または Zotero からエクスポート) |
| `.cls` |ドキュメントクラス |まれに、ベンダー テンプレート |
| `.sty` |パッケージ/スタイルファイル |独自のマクロを作成する場合 |
| `.bst` | BibTeX スタイル |めったに |
| `.aux` |相互参照データ | **いいえ:** が生成されました |
| `.log` |コンパイラ ログ |デバッグ時に読む |
| `.pdf` |出力 |表示/送信 |

## スケーラブルなプロジェクト レイアウト

```text
paper/
 main.tex
 chapters/
 figures/
 refs.bib
```

最上位の 1 つの `main.tex` がエントリ ポイントとして機能し、章は独自のフォルダーに存在し、`\input` または `\include` で取り込まれ、画像は `figures/` に配置され、参考文献は 1 つの `refs.bib` に保持されます。このレイアウトは、プロジェクトが 4 ページの論文であっても、論文であっても管理しやすいものです。 [章ファイルの分割](/learn/split-chapter-files/) は、部分がどのように接続されているかを示します。

Git を使用する場合は、`*.aux`、`*.log`、およびその他の生成されたファイルを `.gitignore` に追加して、履歴が実際のソースのみを追跡できるようにします。 Oleafly プロジェクトはディスク上のプレーン フォルダーであるため、このアドバイスはそのまま適用されます。最も一般的な間違いはその逆です。奇妙なコンパイル エラーを探しているときに、`.aux` ファイルを削除することで解決することがよくあります。壊れた実行による古いファイルは、その後のすべてのコンパイルに悪影響を与える可能性があるためです。
