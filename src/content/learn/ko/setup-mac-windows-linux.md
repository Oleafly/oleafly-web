# 모든 OS에서 작동하는 TeX를 얻습니다.

LaTeX를 로컬에서 작성하려면 소스와 수천 개의 패키지 문서를 컴파일하는 엔진인 TeX 시스템이 필요합니다. 하나를 얻는 데는 두 가지 합리적인 방법이 있습니다. 하나는 엔진이 내장된 애플리케이션으로, 몇 분 안에 컴파일이 가능합니다. 다른 하나는 모든 편집자가 사용할 수 있는 완전한 명령줄 도구 체인을 설치하는 전체 TeX 배포판입니다. 두 경로 모두 동일한 위치에서 끝납니다. 즉, '.tex' 파일이 컴퓨터에서 PDF로 변환됩니다.

## 경로 A: 엔진이 포함된 앱

Mac, Windows, Linux용 [Oleafly](https://github.com/Oleafly/Oleafly/releases/latest)를 다운로드하세요. Tectonic 엔진을 번들로 제공하므로 관리할 별도의 TeX 설치가 없습니다. 앱을 열고 프로젝트를 생성하고 컴파일하면 됩니다. 문서가 존재하지 않는 패키지를 사용하는 경우 Tectonic은 요청 시 해당 패키지를 가져옵니다. 이를 위해서는 특정 패키지가 처음 사용될 때 네트워크 연결이 필요하고 그 이후에는 아무것도 필요하지 않습니다. 이 경로는 TeX 설치를 관리하기보다는 문서를 작성하려는 모든 사람에게 적합하며 다른 도구가 읽을 수 있는 일반 `.tex` 및 `.bib` 파일을 디스크에 남겨둡니다.

## 경로 B: 전체 TeX 배포판

배포판을 설치하면 `pdflatex`, `xelatex`, `lualatex` 및 패키지 관리자가 시스템 명령으로 제공됩니다. Mac에서는 macOS용 TeX Live 패키지인 MacTeX를 설치합니다. 멀티 기가바이트 다운로드가 달갑지 않은 경우 BasicTeX는 필요에 따라 TeX Live Utility를 통해 확장하는 작은 코어입니다. Windows에서는 MiKTeX가 일반적인 선택이며 컴파일 중에 누락된 패키지를 즉시 설치할 수 있으며 TeX Live도 똑같이 잘 작동합니다. Linux에서는 패키지 관리자에서 `texlive-full`을 설치하여 모든 것을 한 번에 설치하거나 `texlive-latex-extra`와 같은 더 작은 구성과 나중에 패키지를 추가하기 위한 `tlmgr` 도구를 설치하세요. 전체 설치에는 시간이 걸리고 몇 기가바이트의 디스크가 필요합니다.

## 설치 확인

터미널을 열고 엔진에 버전을 문의하세요.

```bash
pdflatex --version
# or
xelatex --version
```

버전 배너는 툴체인이 경로에 있고 준비가 되었음을 의미합니다. 명령을 찾을 수 없다는 오류는 일반적으로 설치 프로그램의 PATH 변경 사항이 아직 적용되지 않았음을 의미합니다. 터미널을 다시 시작하거나 Windows에서 로그아웃했다가 다시 로그인하면 문제가 해결됩니다.

## 어떤 길을 택할 것인가

처음 시작하거나 단순히 컴파일된 PDF에 대한 최단 경로를 원하는 경우 앱을 선택하십시오. 특정 엔진, 명령줄 빌드 또는 기존 편집기와의 통합이 필요한 경우 전체 배포를 선택하세요. 두 가지가 충돌 없이 공존하므로 경로 A로 시작하고 나중에 경로 B를 추가하면 비용이 전혀 들지 않습니다. 어느 쪽이든 다음 단계는 동일합니다: [첫 번째 문서](/learn/first-document/)를 컴파일합니다.
