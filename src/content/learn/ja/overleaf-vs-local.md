# ブラウザプロジェクトとディスク上のフォルダー

LaTeX を書き始めると、早い段階で決断を迫られることになります。プロジェクトは他の人のサーバー上のブラウザ タブに存在するのか、それとも自分のディスク上のフォルダーに存在するのか、ということです。どちらのモデルも同じ PDF を生成します。それらは、誰がソースを保持しているか、ネットワークが切断されたときに何が起こるか、および周囲のツールチェーンをどの程度制御するかという点で異なります。

## 各モデルが提供するもの

| |クラウド (例: オーバーリーフ) |ローカル (Oleafly、TeX Live) |
| --- | --- | --- |
|セットアップ |インスタント、インストールする必要はありません | 1 回のインストール |
|オフライン |限定 |編集は常に機能します。コンパイルはキャッシュされたパッケージで実行されます。
|プライバシー |プロバイダーはプロジェクトを保存します |ファイルはディスク上に残ります |
|ギット |同期ブリッジ経由 |ネイティブ、フォルダー内の実際のリポジトリ |
|コラボレーション |リアルタイム カーソル | Git、パッチ、共有フォルダー |
|コスト |無料利用枠とサブスクリプション |無料 |

クラウド プロジェクトは、サービスがレンダリングするデータベース内の行です。ローカル プロジェクトは、ファイル マネージャーで開いたり、USB ドライブにコピーしたり、任意のツールで検索したり、通常の Git でバージョンを作成したりできるディレクトリです。この違いは、締め切りが停止、ペイウォールの変更、またはフライトと一致するまでは抽象的に聞こえます。

## クラウドが正しい選択である場合

リアルタイムの共同編集はクラウドの真の利点です。締め切り前の最後の 1 時間に 3 人の共著者が同じ段落に入力する必要があり、誰もソフトウェアをインストールしない場合、ブラウザ エディタが実用的な解決策になります。現在、同時カーソルに代わるローカルなものはありません。

## ローカルが正しい選択の場合

ドラフトが機密であるか未公開である場合、飛行機または制限されたネットワークで作業している場合、図やデータが大きい場合、またはサブスクリプション層に依存しないバージョン履歴が必要な場合は、ローカルが優先されます。ローカル Git リポジトリは、明日サービスが存在するかどうかに関係なく変更を記録し、同じフォルダーがターミナル、コード エディター、またはコラボレーターのクローンで動作します。

Oleafly は、このテーブルのローカル側用に構築されています。コンパイラーはアプリ内に同梱されており、プロジェクトは実際の G​​it 履歴を含むプレーンなフォルダーであり、オプションの AI は独自のキーで実行されます。より長い比較は [ブログ](/blog/local-first-vs-cloud-latex-editors/) にあり、ドキュメントでは GitHub を通じて [2 つのモデルがどのように連携できるか](/docs/why-oleafly/) について説明されています。
