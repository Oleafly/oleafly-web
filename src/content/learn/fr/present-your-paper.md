# Conférences, affiches et la conférence elle-même

E-mail d'acceptation, prêt à photographier, vols réservés. Maintenant, la partie que personne n'enseigne : la conférence. Voici ce qui se passe réellement et comment bien l’utiliser.

## Le discours

Si votre article bénéficie d'une place orale, vous ferez une présentation, généralement de 10 à 20 minutes plus des questions. Le calcul est brutal et libérateur : on ne peut pas présenter le papier. Vous pouvez présenter une idée, un chiffre clé et une raison d’aller lire le journal.

- [ ] Une phrase à retenir dont le public devrait se souvenir
- [ ] Environ une diapositive par minute, moins c'est bien
- [ ] Grandes polices, gros chiffres, texte minimal
- [ ] Répétez à voix haute au moins trois fois, une fois pour le timing seul
- [ ] Préparez-vous aux deux questions les plus probables

Construisez le deck dans LaTeX pour que votre notation corresponde au document : [Bases de Beamer](/learn/beamer-basics/) vous y amène.

## La session posters

Les articles les plus acceptés sont présentés sous forme d'affiches, et les séances d'affiches constituent souvent la meilleure partie d'une conférence : deux heures de conversation directe avec exactement les personnes qui ont choisi de s'arrêter à votre travail. Concevez-en un lisible à deux mètres et préparez trois versions de votre pitch : la version de 30 secondes pour les passants, la version de 2 minutes pour les intéressés et la version longue pour la personne qui lit votre article dans l'avion. Voir [affiches de la conférence](/learn/conference-poster/) pour le côté LaTeX.

## Discussions et enregistrements éclair

Deux formats qui surprennent les débutants :

- **Lightning talks** : certains lieux accordent à chaque affiche un créneau teaser de 1 à 2 minutes. Une diapositive, une affirmation : « venez me trouver à l'affiche 42 ».
- **Enregistrements** : de nombreuses conférences nécessitent une vidéo préenregistrée de votre intervention, mise en ligne des semaines avant l'événement, avec sa propre date limite. Vérifiez attentivement le courrier électronique d'instructions du présentateur ; ce délai se cache dans le paragraphe quatre.

## Le réseautage est le véritable point

Les discussions sont enregistrées. Les journaux sont en ligne. La seule chose que vous ne pouvez pas télécharger plus tard, c'est le couloir : conversations entre les sessions, questions sur votre affiche, dîner avec des personnes qui citent les mêmes articles que vous. Certaines de ces conversations se transforment en collaborations, en offres postdoctorales et en collègues à vie.

Si le réseautage vous semble terrifiant, utilisez le code de triche intégré : interrogez les gens sur leur travail. Les chercheurs adorent parler de leur travail, et "J'ai vu votre affiche, comment avez-vous géré X ?" est une stratégie sociale complète. Assistez également à des conférences légèrement en dehors de votre région ; c'est de là que naissent les nouvelles idées.

## Artefacts et publication de code

Les attentes ont changé : les évaluateurs et les lecteurs s’attendent de plus en plus à ce que le code, les données ou les artefacts derrière un article soient publics. De nombreux sites proposent des pistes d'évaluation des artefacts avec des badges. Version pratique :

- [ ] Dépôt public avec un README indiquant comment reproduire les principaux résultats
- [ ] Versions de dépendance de broches
- [ ] Liez le dépôt du journal et de l'affiche
- [ ] Licence explicite du code

Si votre projet réside déjà dans Git avec la synchronisation GitHub (voir [sync with GitHub](/learn/sync-with-github/)), la version est principalement une passe de nettoyage, pas une migration.

## Après la conférence

Publiez la version finale là où les gens peuvent la trouver, mettez à jour votre site Web et partagez le message à retenir en une phrase. Alors repose-toi. La leçon suivante, [votre premier article, de bout en bout](/learn/first-paper-roadmap/), place l'ensemble de ce pipeline sur une seule carte.
