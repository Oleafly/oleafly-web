# 只講 Word 的合著者

混合工具協作很常見：您用 LaTeX 撰寫論文，而合著者、顧問或臨床合作者僅在 Microsoft Word 中工作。這兩種格式之間沒有什麼可以完美轉換。儘早就哪個文件才是真正的論文達成一致，然後製定一個例行程序，在不失去工作的情況下跨越差距傳遞回饋。

## 事實的一個來源

儘早確定“.tex”文件是規範的，其他所有文件都是派生副本以供審查。當兩個「當前版本」以兩種格式存在時，某人的編輯就會丟失，並且透過肉眼將 Word 文件與 LaTeX 文件進行協調是一項痛苦的工作。根據本協議，您的工作是排版和整合。您的合著者的工作是內容和評論，以他們喜歡的任何工具提供。

## 根據回饋類型選擇匯出

如需閱讀和進階評論，請發送已編譯的 PDF。每個 Word 使用者都可以開啟 PDF，並且任何 PDF 閱讀器中的註釋工具都包含頁邊註釋和突出顯示。手動應用回饋可以讓您完全控制來源。

當合著者需要提出帶有追蹤變更的句子級重寫時，請匯出 DOCX。 Pandoc 可以很好地將 LaTeX 轉換為 Word 以便審閱，並且 Oleafly 內建了 DOCX 匯出功能。預計轉換是近似的：方程式、交叉引用和圖形位置會降低，您應該提前說明，這樣就沒有人在一次性副本中報告佈局問題。

## 合併會話

「.docx」中的回饋必須手動返回「.tex」。將其視為一項計劃任務而不是持續的細流：收集合著者跟踪的更改，並排打開 Word 文件和 LaTeX 源代碼，並逐一應用已接受的編輯，邊做邊提交到 Git，以便每一輪反饋都是一次提交。有一個規則可以保證這一點：每一輪審核都從目前來源的新匯出開始。切勿讓同一個 Word 檔案存在於多個輪次中，因為它會默默地分叉紙張。

## 當 Word 中開始草稿時

有时流程会相反：合著者在 Word 中编写初稿，而您负责排版。儘早轉換一次。 Oleafly 將 `.docx` 匯入 LaTeX 項目，pandoc 在命令列上執行相同的操作。從那時起，`.tex` 就是規範的，並且上面的例程適用。對於使所有這些都可恢復的版本控制主幹，請參閱[將論文放在 GitHub 上](/learn/sync-with-github/)。
